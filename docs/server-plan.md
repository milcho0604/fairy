# 페어리 서버 기획서 (2026-10-14 확정)

## 1. 원칙
- **사용자 컴퓨터가 기본, 서버는 꼭 필요한 일만.** 펫, 할 일, 일정, 집중, 코인 벌기와 쓰기, 상점, 내 AI(CLI) 대화는 지금처럼 전부 앱 안에서 돈다.
- 서버가 맡는 일은 셋뿐이다: **비밀을 쥐어야 하는 일**(API 키), **여러 사람 사이에서 한 번만이어야 하는 일**(쿠폰, 지급), **사람을 알아봐야 하는 일**(계정).
- 서버가 죽어도 앱은 멈추지 않는다. 서버 기능만 "잠시 뒤 다시"가 된다.
- 서버에 펫 데이터, 할 일, 대화 내용은 두지 않는다. 개인정보는 최소로.

## 2. 누가 무엇을 하나
| 기능 | 사용자 앱 | 서버 | 서버 꺼지면 |
|---|---|---|---|
| 펫, 할 일, 일정, 집중, 상점 | 전부 | 없음 | 영향 없음 |
| 코인 벌기와 쓰기 | 서버 잔액 사본, 기록을 모아 보냄 | 정본 잔액과 규칙 확인 | 사본으로 계속, 살아나면 맞춤 |
| 서버가 준 코인(이벤트, 쿠폰, 개인 지급) | 받은 기록을 장부에 한 번 적기 | 지급 내역, 한 번만 보장 | 다음에 켜질 때 받음 |
| 이벤트 목록 | 하루 한 번 받아 캐시 | **홈서버 아님: 홈페이지(Vercel) 정적 파일** | 영향 없음 (캐시, 정적 파일은 홈서버와 무관) |
| 쿠폰 입력 | 입력 칸 | 코드 확인, 한 번만, 전체 상한 | "잠시 뒤 다시" |
| 계정 로그인 | 브라우저로 로그인 시작, 세션 보관 | 구글, 카카오 확인 후 세션 발급 | 이미 로그인한 사람은 그대로, 새 로그인만 안 됨 |
| AI 대화권 | 남은 횟수 표시, 내 CLI 와 고르기 | API 키 보관, 횟수 차감, Claude 호출 중계 | 내 CLI(Claude, Codex, Gemini 등)로 그대로 대화 |
| 운영자 화면 | 없음 | 이벤트, 쿠폰, 지급, 사용량 보기 | 운영만 멈춤 |

서버 부담: 이벤트 목록은 정적 파일이라 0. 로그인과 쿠폰은 드물다. 실제 일은 AI 중계 하나인데, 계산은 Anthropic 이 하고 서버는 글자를 넘겨 주기만 해서 맥미니에 거의 부담이 없다.

## 3. 계정
- **로그인 없이도 지금 기능은 전부 쓴다.** 로그인은 AI 대화권, 쿠폰, 개인 지급을 받을 때만.
- 구글 로그인: `openid` 와 `profile` 만 쓰면 민감 범위가 아니라 심사가 필요 없다(민감 범위를 더할 때만 심사). 사업자 불필요. 일정 연동용 OAuth 앱과는 따로 만든다(그쪽은 검수 진행 중).
- 카카오 로그인: 닉네임 같은 기본 항목은 사업자 없이 된다. 이메일은 "개인 개발자 비즈 앱" 전환(본인인증, 사업자 불필요)이 필요하다고 알려져 있다(카카오 개발자 포럼 근거, 공식 문서로 재확인 필요). → **이메일을 받지 않으면 둘 다 심사 없이 시작 가능.**
- 서버에 남기는 것: 로그인 종류, 그 서비스의 사용자 번호(sub), 표시 이름, 가입일. **이메일은 받지 않는 것을 추천.**
- 데스크톱 로그인 흐름: 앱이 브라우저를 연다 → 구글/카카오 로그인 → 서버 콜백 → 앱 주소(fairy://)로 돌아와 서버 세션을 받는다. (카카오가 localhost 리디렉트를 받는지는 구현 전 확인)
- 만 14세 미만도 쓴다. 나이 확인 칸은 두지 않는다.
  - 개인정보보호법 제22조의2 의 법정대리인 동의는 "동의를 받아야 할 때"에만 걸린다. 서비스 제공에 꼭 필요한 최소 정보만, 동의가 아닌 서비스 제공(계약 이행, 제15조 1항 4호)을 근거로 처리하고 선택 동의 항목(광고, 마케팅, 이메일)을 두지 않으면 걸리지 않는다는 해석이 일반적이다(개인정보보호위원회 해설로 재확인 필요).
  - 구글과 카카오도 만 14세 미만 계정은 이미 보호자(Family Link, 카카오 보호자 동의)를 거친다.
  - 이용약관과 개인정보처리방침에 "서비스 제공에 필요한 최소 정보만, 광고와 마케팅에 쓰지 않음, 탈퇴 즉시 삭제"를 적는다.
  - AI 대화권은 아동도 쓸 수 있으므로 Anthropic 이용 정책의 미성년자 관련 조건을 구현 전 확인한다(시스템 프롬프트 안전 지침, 신고 수단 등).
- 탈퇴: 앱 설정에서 바로. 서버 기록 삭제.
- 사람은 이메일이 아니라 구글, 카카오의 계정 고유 번호(sub)로 알아본다. 이메일이 없어도 같은 구글 계정이면 같은 사람이다.

### 다른 PC 에서
| 경우 | 결과 |
|---|---|
| 새 PC 에서 같은 계정으로 로그인 | 코인과 AI 대화권이 따라온다 |
| 로그인 없이 두 PC 에서 씀 | 기기 계정이 둘, 코인이 따로 쌓인다. 둘 다 같은 계정으로 로그인하면 한 번 합친다 |
| 한 PC 는 구글, 다른 PC 는 카카오 | 이메일로 맞출 수 없어 계정이 둘. 설정의 "카카오도 연결"로 한 계정에 둘 다 붙인다 |
| 펫, 할 일, 일정 | 서버에 없다. 지금처럼 백업 파일로 옮긴다 |

## 4. AI 대화권 (Claude Max 월 API 크레딧 활용)
### 확인한 사실
- Max 5x 는 매달 API 크레딧 100달러, Max 20x 는 200달러. Claude API 에 쓸 수 있고, Claude Code 에는 안 쓰인다. 매 결제 주기마다 새로 들어오고 남은 것은 이월되지 않는다.
- 크레딧은 콘솔 조직에 들어오고, 공식 문서 표현으로 "자기 앱과 에이전트를 만들고 돌리는 데" 쓴다. 크레딧 약관은 크레딧을 남에게 넘기거나 팔지 못하고 계정 주인만 쓴다고 정한다.
- 해석: 우리 서버가 우리 키로 API 를 부르고 사용자는 그 결과만 받으므로 "넘기기"가 아니라 우리 앱의 사용이다. 다만 이것은 내 해석이고, API 이용 정책(Usage Policy)상 사용자 대화 내용에 대한 책임은 우리에게 있다.
- 크레딧이 떨어지면 API 가 멈출 뿐 Max 요금으로 청구되지 않는다. 그래도 워크스페이스 지출 상한을 따로 건다.

### 비용 감 (Haiku 5.5, 입력 100만 토큰 0.10달러, 출력 0.50달러)
- 한 번 대화(입력 2,000, 출력 300 토큰) 약 0.00035달러 → 100달러로 약 28만 번.
- Sonnet 5.5(입력 2달러, 출력 10달러)면 한 번 약 0.007달러 → 약 1만 4천 번.
- → **Haiku 5.5 로 시작 추천.** 대화권 10개는 사실상 비용이 거의 없다.

### 설계
- 첫 로그인 선물: AI 대화권 10개 (1개 = 질문 1번).
- 서버가 차감과 호출을 같이 한다(앱은 키를 모른다). 실패하면 차감 취소.
- 한 번 대화 상한: 입력과 출력 토큰 상한, 대화 기록은 앱이 최근 몇 개만 보낸다. 서버는 내용을 저장하지 않는다(사용량 숫자만).
- 안전장치: 사람별 하루 상한, 서버 전체 월 상한(예: 80달러에서 멈춤), 콘솔 워크스페이스 지출 상한, 운영자 화면에 사용량.
- 다 쓰면: "대화권을 다 썼어. 내 컴퓨터의 AI 로 이어서 할까?" 로 기존 CLI 로 넘긴다.
- 대화권 늘리기: 이벤트, 쿠폰, (나중에) 코인으로 바꾸기. 코인 교환을 넣으면 코인이 비용과 이어지므로 그때 코인 규칙을 다시 본다.

## 5. 코인 (서버가 관리, 사용자 결정 2026-10-14)
- 지금 사용자는 친구들뿐이라 코인은 서버가 정본으로 관리한다.
- **로그인 없이도 서버 코인:** 앱을 처음 켜면 서버가 이름 없는 계정(기기 계정)을 하나 만들어 준다. 로그인은 나중에 그 계정에 구글이나 카카오를 이어 붙이는 것. 그래서 로그인 안 한 사람도 코인이 서버에 있다. 기기를 바꾸거나 다시 설치하면 로그인한 계정만 코인을 되찾는다.
- **서버가 꺼져도 코인은 계속:** 앱이 서버 잔액의 사본을 들고 있다. 벌기는 앱이 기록해 두었다가 서버가 살아나면 묶어서 보낸다. 쓰기(상점)도 사본 잔액 안에서 먼저 하고 나중에 맞춘다. 서버는 받은 기록을 하루 상한 등 규칙으로 확인해 정본에 반영한다.
- 기존 사용자: 첫 연결 때 앱의 지금 잔액을 한 번 서버로 올린다.
- 서버 부담: 코인 기록은 몇 분에 한 번 묶어서 보낸다(요청 수가 작다).
- 코인이 서버에 있으므로 나중에 코인으로 AI 대화권을 바꾸는 것도 안전하게 할 수 있다.

## 6. 운영자
- 서버의 `/admin` 화면, 운영자 토큰(daypoll 과 같은 방식).
- 할 수 있는 것: 이벤트(모두에게 선물, 배수), 쿠폰(코드, 수량, 기간), 특정 사용자 지급, AI 대화권 지급, 사용량과 남은 크레딧 감.
- 이벤트 목록은 운영자 화면에서 만들면 서버가 홈페이지 정적 파일로 내보낸다(또는 레포 site/events.json 을 고쳐 배포). 앱은 정적 파일만 읽는다.

## 7. 기술 틀 (daypoll 과 같게)
- fairy 레포 `server/`, NestJS, Postgres, Docker compose(이름 fairy, 127.0.0.1:3002), Cloudflare Tunnel 에 `fairy-api.moilga.com`, main push 때 Tailscale ssh 배포, 매일 외장 디스크 백업, 10분마다 상태 확인.
- 공개 레포라 비밀은 맥미니 `.env.prod` 와 Actions 시크릿에만. Anthropic API 키도 `.env.prod`.
- 홈서버 한계: 집 인터넷, 전기. 그래서 서버 꺼짐이 앱을 멈추지 않게 위 표대로 설계.

## 8. 단계
1. 기획 확정 (이 문서)
2. 서버 뼈대 + 구글 로그인 + 탈퇴 + 개인정보처리방침
3. AI 대화권 (첫 로그인 10개, Haiku 5.5, 상한들)
4. 이벤트 정적 파일 + 쿠폰 + 개인 지급 + 운영자 화면
5. 카카오 로그인
