# 짝꿍 진행표

기획서 [개발 단계](plan.md#개발-단계)를 실제 작업 단위로 쪼갠 계획이자 체크리스트다. 작업 하나를 끝낼 때마다 체크하고 커밋한다.

## 쓰는 규칙

- **상태**: `[x]` 완료, `[ ]` 할 일, `[~]` 진행 중이거나 일부만 됨, `[-]` 보류나 다른 작업으로 옮김
- **작업 ID**: `P<단계>-<번호>`. 커밋 메시지와 작업 기록에 ID 를 적는다.
- **추정**: 작업한 시간(대기 시간 제외). 단계가 끝나면 실제 시간을 요약 표에 적고, 차이가 크면 다음 단계 추정을 고친다.
- **다음 단계로 가는 조건**: 그 단계의 완료 기준을 모두 넘어야 한다. 못 넘으면 원인을 "위험 관찰"에 적고 결정한다.
- **확인**: 각 작업의 "확인"은 끝났다고 말하기 전에 실제로 해 볼 일이다. 말로 끝내지 않는다.
- **디자인 점검** (사용자 요청 2026-10-02): 화면을 바꾼 작업은 끝낼 때 상태별로 화면을 찍어 눈으로 본다. 밝은 모드와 어두운 모드, 채팅 창 기본 폭(400)과 가장 좁은 폭(320), 긴 글과 긴 URL, 펫 크기 50%와 300%, 화면 끝. 점검 스크립트 방식은 작업 기록 2026-10-02 "디자인 점검" 참고
- **최적화** (사용자 요청 2026-10-02): 화면이나 상시 동작을 바꾸는 작업은 끝낼 때 CPU 와 메모리를 재서 결과에 적는다. 측정은 `JJ_METRICS=5 npm run dev`(합계와 프로세스별)와 `top` 교차 확인(L11). 기준은 대기 CPU 1% 이하, 잠 0.3% 이하, 1단계 메모리 350MB 이하. 늘었으면 원인을 찾고 줄일 방법을 같이 시험한다

**다시 켜는 법**

- 개발: `npm install` 뒤 `npm run dev`. 확인은 `npm run check` (타입 검사, 린트, 테스트 119개). 커밋은 `npm run check` 가 통과할 때만
- 설치 파일: `npm run dist:mac`(dmg 애플 실리콘과 인텔, `dist/`), 윈도우는 GitHub Actions release. 설치판을 실제 데이터와 따로 띄워 점검하려면 `JJ_USER_DATA=<빈 폴더> dist/mac-arm64/Jjakkung.app/Contents/MacOS/Jjakkung --inspect=9239 --remote-debugging-port=9354` (설치판에는 `__jj` 가 없어 메인 디버거에서 `require('electron')` 으로 다룬다)
- 실제 앱으로 점검: `scripts/dev/README.md` (DevTools 포트와 메인 디버거로 상태를 넣고 화면을 찍는다). 화면을 바꾼 작업은 밝은, 어두운, 좁은 화면을 찍어 본다(쓰는 규칙 "디자인 점검")
- 사용자 데이터(맥): `~/Library/Application Support/jjakkung/` 에 `settings.json`, `jjakkung.db`(할 일, 코인), `pet-position.json`, `chat-settings.json`, `ai-usage.json`, `ai-custom.json`, `ai-env.json`(로그인 셸 PATH), `codex-home/`(codex 격리), `ai-workdir/`, `models/`(배경 제거 모델 170MB), `pets/`(사진 펫 그림)
- 코드 지도: 메인 `src/main/` (index 가 모두 잇는다: pet-window, chat, panel, look-together, maker, settings-window, tray, db, ai/runner), 화면 `src/renderer/` (pet 은 React 없이, 나머지는 React), 순수 로직과 시험 `src/shared/`

## 0단계에서 배운 것 (뒤 단계에 반영)

실험에서 확인한 사실이다. 해당 작업에 반영했는지 체크한다.

- [ ] L1 **CLI 경로는 한 번 찾고 저장한다.** Finder 로 연 앱은 PATH 가 `/usr/bin:/bin:/usr/sbin:/sbin` 뿐이라 `~/.local/bin/claude` 를 못 찾는다. 로그인 셸로 찾으면 약 2초 걸린다. → P3-01
- [~] L2 **권한 시험은 앱을 단독 실행해서 한다.** 터미널에서 띄우면 캡처가 실제로 안 되는데도 권한이 `granted` 로 읽힌다. → P0-05, P3-05
- [x] L3 **왼쪽 버튼만 클릭으로 처리한다.** 실험 앱에서 우클릭 뒤 클릭이 한 번 더 들어오는 버그가 있었다. → P1-02
- [ ] L4 **codex 답은 한 번에 온다.** 조각 스트리밍이 없어 8초 안팎을 "생각 중" 동작으로 채운다. claude 는 조각으로 온다. → P3-03, P3-04
- [ ] L5 **AI 는 격리해서 부른다.** claude 는 `--setting-sources ""` 와 `--tools ""`, codex 는 임시 `CODEX_HOME` 에 `auth.json` 링크. codex 설정 폴더는 다른 앱(Orca)이 바꿔 둘 수 있다. → P3-02, P3-03
- [ ] L6 **메모리 예산이 빠듯하다.** 펫 창 하나에 325MB. 패널과 채팅 창은 열 때 만들고 닫으면 없앤다. 창 세 개 400MB 목표를 단계마다 잰다. → P1-02, P2-02, P3-04
- [x] L7 **모니터 좌표는 음수가 될 수 있다.** 이 맥은 내장 화면이 x = -1512 에 있다. 좌표 계산과 위치 저장에서 음수를 허용한다. → P1-02, P1-04
- [ ] L8 **대화가 길면 토큰이 쌓인다.** codex 이어가기 2번째에 입력 54,099 토큰. 일정 길이를 넘으면 새 대화를 권한다. → P3-04
- [x] L9 **Vite 는 7 에 묶인다.** electron-vite 5.0.0 이 Vite 5~7 만 지원한다(최신은 8.3). Vite 8 로 가려면 electron-vite 새 판을 기다리거나 직접 설정한다. → P1-01 반영
- [x] L10 **계속 도는 애니메이션은 fps 를 낮춰도 CPU 를 먹는다.** 펫 창에서 CSS 무한 애니메이션은 합계 6.1%, 끄면 0.0%. JS 로 30fps, 15fps 로 낮춰도 6.1%, 6.3% 로 그대로였다 (`top` 측정). 기본 상태에서도 "가만히 있다가 가끔 움직이기"로 설계하고, 움직이지 않을 때는 그리기를 완전히 멈춘다. → P1-03, P1-06
- [ ] L11 **CPU 측정 방법을 하나로 정한다.** 같은 실험 앱이 `app.getAppMetrics` 로는 0.65%, `top` 으로는 2.52% 였다. 앞으로 단계별 비교는 `JJ_METRICS=<초> npm run dev` (getAppMetrics) 로 하고, 의심스러우면 `top` 으로 교차 확인한다. → 모든 단계
- [x] L12 **GPU 를 본체 프로세스 안에서 돌리면 메모리가 크게 준다.** `--in-process-gpu` 로 363MB 에서 306MB, 프로세스 4개에서 3개. CPU 는 같았다(신남 5.8% 대 5.5%, 오차 범위). `--disable-gpu` 는 348MB. 기본으로 켜고 `JJ_GPU_PROCESS=1` 로 끈다. GPU 문제가 나면 앱 전체가 죽는 대가가 있다. 윈도우에서 다시 확인 → P0-W4
- [x] L13 **claude 는 격리해도 claude.ai 커넥터 MCP 도구가 실릴 때가 있다.** 같은 명령인데 한 번은 도구 106개, 입력 104,171 토큰($0.83), 다른 때는 0개, 10,292 토큰이었다. `--strict-mcp-config --mcp-config '{"mcpServers":{}}' --disable-slash-commands` 로 늘 뺀다. `--bare` 는 구독 로그인(OAuth)을 안 읽어서 못 쓴다 → P3-02 반영
- [x] L14 **codex 는 node 스크립트다.** `#!/usr/bin/env node` 라 Finder 로 연 앱에서는 node 도 못 찾는다. CLI 경로만이 아니라 로그인 셸의 PATH 를 통째로 쓴다 → P3-01 반영
- [ ] L15 **electron-vite 5.0.0 의 `isolatedEntries` 는 터미널이 아니면 빌드가 죽는다** (`process.stdout.clearLine is not a function`). preload 를 입구 여러 개로 나누면 공유 조각이 생겨 샌드박스에서 못 읽으므로, preload 는 한 파일로 두고 창 종류를 실행 인자(`--jj-window=`)로 나눈다. electron-vite 새 판에서 다시 본다
- [x] L16 **맥 메뉴 막대가 붐비면 아이콘이 안 보인다.** 메뉴 막대 아이콘을 만들었는데 위치가 화면 밖(x = -1927)으로 나왔다. 아이콘이 많거나 노치가 있으면 맥이 뒤쪽 아이콘을 감춘다. 숨은 펫을 다시 부르는 길을 아이콘 하나에 맡기지 않는다: 단축키, 숨기 전 안내 말풍선, 다시 실행하면 나오기 → P1-10 반영
- [x] L17 **SQLite 는 `node:sqlite` 로 네이티브 모듈 없이 된다.** Electron 44 에 든 Node 24.21 에 SQLite 3.53.4 가 들어 있다. better-sqlite3 처럼 Electron 판에 맞춰 다시 빌드할 일이 없어 맥, 윈도우 설치 파일 위험이 하나 준다. 시험(Node 25)에서도 같은 것을 쓴다 → P2-01 반영
- [ ] L18 **맥은 전역 단축키가 겹쳐도 등록 성공으로 나온다.** 다른 앱이 먼저 잡은 키를 짝꿍이 다시 등록해도 `register` 가 true 다. 겹침 안내는 윈도우에서만 뜬다. 맥은 설정에서 단축키를 바꿀 수 있게 하는 쪽으로 푼다 → v1 단축키 바꾸기
- [x] L19 **onnxruntime-web 1.30 의 GPU 묶음은 asyncify 엔진 파일을 쓴다.** 엔진 파일 위치를 jsep 판으로 지정했더니 "reading 'Xe'" 오류로 배경 지우기가 멈췄다. 위치를 지정하지 않으면 Vite 가 묶음 옆에 맞는 판을 내보내고 묶음이 스스로 찾는다 → P1-08 반영
