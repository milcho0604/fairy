# 페어리 설치 안내

페어리는 아직 애플과 마이크로소프트의 개발자 서명을 받지 않았다(D4). 그래서 처음 열 때 한 번 경고가 뜬다. 아래대로 한 번만 넘기면 그다음부터는 그냥 열린다.

설치 파일은 공개 레포 fairy-releases 의 GitHub 릴리스 페이지(<https://github.com/milcho0604/fairy-releases/releases/latest>)에 있다. 받은 파일이 올린 것과 같은지는 같이 올린 `SHA256SUMS.txt` 로 확인할 수 있다(리눅스 `sha256sum -c SHA256SUMS.txt --ignore-missing`, 맥 `shasum -a 256 <파일>`, 윈도우 PowerShell `Get-FileHash <파일>` 의 값을 목록과 견준다).

## 필요한 것

| | 내용 |
| --- | --- |
| 맥 | macOS 13(Ventura) 이상. 애플 실리콘(M1 이후)과 인텔 둘 다 |
| 윈도우 | Windows 10 이상, 64비트(x64). ARM 윈도우는 지원하지 않는다 |
| 리눅스 (시험판) | x64. 데스크톱 환경(X11 또는 Wayland), 투명 창이 되는 컴포지터 |
| 디스크 | 앱 약 300MB(리눅스 0.1.0 풀린 크기 294MB 기준). 무료 AI 모델 400MB~1GB, 사진 페어리 도구 약 200MB 는 쓸 때만 받는다 |
| AI 대화 | 아래 "AI 연결" 중 하나. 없어도 페어리, 할 일, 메모, 일정은 다 된다 |

설치 파일 크기(리눅스 0.1.0 실측, 2026-10-11): `tar.xz` 약 86MB, `AppImage` 약 100MB. 맥과 윈도우는 릴리스 페이지에 크기가 보인다. 무료 AI 를 처음 쓸 때 모델과 함께 엔진(5~11MB)을 한 번 받는다.

## 맥

맥 OS 15(Sequoia) 이상 기준이다. 이전 판에서는 앱을 우클릭해 "열기"를 눌러도 된다.

1. 받을 파일 고르기
    - 애플 실리콘(M1 이후): `fairy-<버전>-mac-arm64.dmg`
    - 인텔: `fairy-<버전>-mac-x64.dmg`
    - 모르겠으면 화면 왼쪽 위 사과 메뉴 → 이 Mac에 관하여 → "칩"이 Apple M 으로 시작하면 애플 실리콘이다.
2. dmg 를 열고 **fairy** 를 응용 프로그램 폴더로 끌어 넣는다.
3. 응용 프로그램 폴더에서 fairy 를 연다. "Apple은 ‘fairy’에 사용자의 Mac에 손상을 입히거나 사용자의 개인정보에 침입할 수 있는 악성 코드가 없음을 확인할 수 없습니다." 창이 뜨면 "완료"를 누른다. (휴지통으로 옮기지 않는다.) 애플 개발자 서명(유료) 전이라 처음 한 번 뜨는 창이고, 앱이 망가진 것이 아니다.
4. 시스템 설정 → **개인정보 보호 및 보안** → 아래쪽 "보안" 칸에서 "Mac을 보호하기 위해 ‘fairy’을(를) 차단했습니다." 옆의 **그래도 열기** 를 누른다. 맥 암호를 넣는다.
5. 다시 뜨는 창에서 **그래도 열기** 를 누르면 화면에 페어리가 나온다.

그래도 열리지 않으면 터미널에서 아래 한 줄을 실행한 뒤 다시 연다. 인터넷에서 받은 파일 표시를 지우는 명령이다.

```bash
xattr -dr com.apple.quarantine /Applications/fairy.app
```

dmg 안에서 바로 열지 말고 응용 프로그램 폴더로 옮긴 뒤 연다. dmg 안이나 격리 표시가 남은 채로 돌면 자동 업데이트가 설치를 거절한다(그때 페어리는 홈페이지 [맥에 설치하기](https://fairy.moilga.com/download/#mac-t)를 연다).

"손상되었기 때문에 열 수 없습니다" 창이 뜨면 휴지통으로 옮기지 말고 "취소"를 누른 뒤 위 명령을 실행한다. 새 버전을 홈페이지에서 직접 받아 다시 설치하면 이 경고가 한 번 더 뜬다. dmg 창 아래 "열리지 않으면 여기 (If it won't open)" 링크는 홈페이지 설치 안내로 간다.

### 같이 보기 권한 (화면 기록)

"같이 보기"는 고른 화면 영역을 찍어 AI 에게 보여 준다. 처음 쓸 때 맥이 화면 기록 권한을 묻는다.

1. 페어리가 "화면 기록 권한이 필요해" 안내를 띄우면 **설정 열기** 를 누른다.
2. 시스템 설정 → 개인정보 보호 및 보안 → **화면 및 시스템 오디오 녹음** 에서 fairy 를 켠다.
3. 맥이 "종료 후 다시 열기"를 물으면 그렇게 한다. 권한은 앱을 다시 켜야 적용된다.

찍은 화면은 디스크에 남기지 않고, 고른 AI 에게만 보낸다. 페어리 자체는 어떤 서버로도 보내지 않는다. 화면을 실은 질문은 Claude Code, Codex 의 대화 기록에도 남기지 않게 부른다.

## 윈도우

1. `fairy-<버전>-win-x64.exe` 를 받아 실행한다.
2. **"Windows의 PC 보호"** 파란 창(SmartScreen)이 뜨면 **추가 정보** → **실행** 을 누른다. 서명이 없는 새 앱이라 뜨는 창이고, "실행" 단추는 "추가 정보"를 눌러야 보인다.
3. 관리자 권한 없이 바로 설치되고 페어리가 나온다. 바탕 화면과 시작 메뉴에 "페어리" 바로 가기가 생긴다(설치 위치 `%LOCALAPPDATA%\Programs\fairy`). 설치 창의 말은 윈도우 언어가 한국어면 한국어, 아니면 영어다.

같이 보기는 윈도우에서 따로 권한을 묻지 않는다. 윈도우판은 아직 확인 중이다([체크리스트](tests/windows.md)).

회사 컴퓨터에서 SmartScreen 이 "실행" 단추 없이 막으면 관리자가 막아 둔 것이다. 이때는 설치할 수 없다(서명 판이 나올 때까지).

## 리눅스 (시험판)

- `fairy-<버전>-linux-x64.tar.xz`: 풀어서 안의 `fairy` 를 실행한다.

    ```bash
    tar xJf fairy-<버전>-linux-x64.tar.xz
    ./fairy-<버전>-linux-x64/fairy
    ```

- `fairy-<버전>-linux-x86_64.AppImage`: 실행 권한을 주고 실행한다(`chmod +x`). 배포판에 따라 `libfuse2` 가 필요하다.
- 리눅스는 자동 업데이트가 없다. 새 버전이 나오면 페어리가 릴리스 페이지를 연다.
- 투명 창이 검게 보이면 컴포지터가 꺼진 것이다. 같이 보기와 창 위에 올라앉기는 데스크톱 환경에 따라 안 될 수 있다.

## AI 연결

페어리는 AI 를 직접 갖고 있지 않고, 이 컴퓨터에 설치해 로그인해 둔 AI 프로그램(CLI)을 부르거나, 컴퓨터 안에서만 도는 무료 AI 를 쓴다.

- **AI 프로그램(CLI)**: Claude Code (`claude`), Codex (`codex`), Cursor (`cursor-agent`), Gemini (`gemini`) 중 하나. 설치와 로그인은 각 프로그램 안내를 따른다. 페어리 채팅 창의 AI 고르기에서 "설치됨, 로그인됨"으로 보이면 된다. 위 목록에 없는 CLI 도 채팅 창에서 직접 추가할 수 있다.
- **무료 AI (CLI 없이)**: 채팅 창의 AI 고르기에서 **무료 AI** 를 고르면 처음 한 번 모델을 받는다(Qwen3 1.7B 약 940MB, 가벼운 0.6B 약 400MB). 그 뒤로는 인터넷 없이 이 컴퓨터 안에서만 돈다. 계정도 사용료도 없다. 큰 AI 보다 답이 짧고 단순하며, 같이 보기(그림)와 페어리 도구는 쓰지 못한다. 받은 모델은 설정 → 데이터 → 저장 공간에서 지운다.
- 페어리는 AI 프로그램에 페어리에 필요한 환경 변수만 넘기고(로그인, 프록시, 언어 등), 기본으로 내 훅, MCP, 스킬 없이 부른다(설정 → AI → "내 AI 설정 없이 부르기").

## 업데이트

새 버전 확인, AI 모델 목록, 페어리 갤러리는 공개 레포 `milcho0604/fairy-releases` 의 릴리스와 `catalog/models.json`, `gallery/` 를 읽는다(소스 레포는 읽지 않는다). 앱 이름과 버전 말고는 보내지 않는다. 레포가 공개되어 있지 않거나 연결이 안 되면 확인만 조용히 건너뛰고, 모델 목록은 앱에 들어 있는 것을 쓴다.

- 맥, 윈도우: 새 버전을 미리 받아 두고 페어리가 "다시 켜서 업데이트"를 띄운다. **누를 때만** 설치한다(끝낼 때 저절로 설치하지 않는다).
- 리눅스: 페어리가 릴리스 페이지를 연다.
- 설정 → 정보 → "새 버전 알림"을 끄면 새 버전 말풍선만 쉰다. 꼭 필요한 업데이트(최소 버전) 확인은 계속한다.
- 0.1.0(공개 전 사설 빌드)은 소스 레포 `milcho0604/fairy` 의 릴리스를 보던 판이라 fairy-releases 에 올라온 새 버전을 스스로 찾지 못한다. 한 번만 릴리스 페이지에서 받아 덮어 설치하면 그다음부터는 저절로 안내된다.

## 짝꿍에서 페어리로

예전 이름은 짝꿍(Jjakkung)이었다. 2026-10-11 부터 앱 이름은 페어리(영어 fairy), 화면 위 친구도 펫이 아니라 페어리라고 부른다.

- **데이터는 저절로 옮겨진다.** 페어리를 처음 켤 때 새 데이터 폴더(`fairy`)가 없고 예전 폴더(`jjakkung`)에 할 일이나 설정이 있으면 예전 폴더를 통째로 새 이름으로 옮긴다(복사하지 않고 이름만 바꿔서 받은 모델도 그대로, 한 번에 되거나 아예 안 된다). 예전 자리에는 어디로 옮겼는지 적은 `MOVED-TO-FAIRY.txt` 만 남는다. 새 폴더에 앱이 스스로 만드는 것(Crashpad, 캐시 등)만 있으면 그것을 `fairy.pre-move-<시각>` 으로 비켜 두고 옮긴다(지워도 된다). 새 폴더에 할 일, 설정 같은 데이터가 이미 있으면 예전 폴더는 건드리지 않는다.
- **짝꿍이 아직 켜져 있으면** 옮기지 못한다. 페어리가 "예전 짝꿍이 아직 켜져 있어" 창을 띄우고 끝나니, 짝꿍을 끝낸 뒤 페어리를 다시 켠다(데이터는 그대로다). 윈도우에서 다른 프로그램이 파일을 열고 있어 못 옮길 때는 이번에는 예전 폴더를 그대로 쓰고 다음에 켤 때 다시 옮긴다. 옮긴 일은 진단 기록(`logs/main.log`)에 `[data]` 줄로 남는다.
- **구글 캘린더는 한 번 다시 연결한다** (맥, 리눅스). 연결 토큰은 운영체제 열쇠(맥 키체인)로 암호화해 두는데 그 열쇠 이름이 앱 이름을 따라가 새 이름으로는 풀지 못한다. 페어리가 "구글 캘린더 연결이 끝났어" 라고 알리면 설정 → 구글 캘린더로 보내기에서 다시 연결한다. 보낸 일정은 겹치지 않는다. 무료 Hugging Face 토큰을 넣어 뒀다면 그것도 다시 넣는다.
- 데이터 폴더: 맥 `~/Library/Application Support/jjakkung` → `fairy`, 윈도우 `%APPDATA%\jjakkung` → `%APPDATA%\fairy`, 리눅스 `~/.config/jjakkung` → `~/.config/fairy`. 저장 파일 이름(`jjakkung.db`)은 그대로다.
- `jjakkung://` 주소(단축어, Raycast)와 `.jjpet` 파일은 그대로 된다. 새로 내보내는 파일은 `.fairy`.
- 다른 AI 에 MCP 서버로 등록해 뒀다면 실행 파일 경로가 바뀌어 다시 등록해야 한다: `claude mcp remove jjakkung -s user` 뒤 설정 → AI → "다른 AI에서 페어리 쓰기"의 새 명령(`claude mcp add fairy ...`), Codex 는 `[mcp_servers.jjakkung]` 조각을 새 `[mcp_servers.fairy]` 조각으로 바꾼다.
- 짝꿍 시험판을 깔았던 컴퓨터는 앱 ID 가 바뀌어(`com.moilga.fairy`) 페어리가 따로 깔린다. 짝꿍 앱은 지우고(데이터는 위처럼 옮겨진다), 맥은 화면 기록 권한과 로그인 시 실행을 페어리에 다시 켠다.

## 지우기

1. (선택) 설정 → 데이터 → **AI 기록 지우기** 를 먼저 누르면 Claude Code, Codex 가 페어리 대화를 남긴 곳까지 지운다.
2. (선택) 설정 → 편의 → 시작 → "컴퓨터를 켜면 같이 켜기"를 끈다.
3. 앱을 지운다.
    - 맥: 메뉴 막대의 페어리 아이콘 → 끝내기, 응용 프로그램 폴더에서 fairy 를 휴지통으로.
    - 윈도우: 설정 → 앱 → 설치된 앱 → 페어리 → 제거. 지우기 전에 데이터는 남긴다는 안내와 남는 폴더(`%APPDATA%\fairy`)가 뜬다.
    - 리눅스: 푼 폴더나 AppImage 파일을 지운다.

할 일, 코인, 설정, 사진 페어리는 앱을 지워도 남는다(다시 설치하면 이어서 쓴다). 완전히 지우려면 아래도 지운다.

| 무엇 | 맥 | 윈도우 | 리눅스 |
| --- | --- | --- | --- |
| 페어리 데이터 전부 (할 일, 페어리, 설정, 토큰, 받은 모델, 내 컴퓨터에서 그리기 도구, 진단 기록, 백업 가져오기 전 복사본) | `~/Library/Application Support/fairy` | `%APPDATA%\fairy` | `~/.config/fairy` |
| 받아 둔 업데이트 | `~/Library/Caches/fairy-updater`, `~/Library/Caches/com.moilga.fairy.ShipIt` | `%LOCALAPPDATA%\fairy-updater` | 없음 |
| Claude Code 가 남긴 페어리 대화 | `~/.claude/projects/` 안의 이름이 `-fairy-ai-workdir` (짝꿍 때 대화는 `-jjakkung-ai-workdir`) 로 끝나는 폴더 | 같은 곳(`%USERPROFILE%\.claude\projects\`) | 같은 곳 |
| Codex 가 남긴 페어리 대화 | 페어리 데이터 폴더의 `codex-home/` (위에서 같이 지워진다). "내 AI 설정 없이 부르기"를 껐을 때는 내 `~/.codex/sessions` 에 섞여 있다 | 같음 | 같음 |
| 맥 권한 목록 | 시스템 설정 → 개인정보 보호 및 보안 → 화면 및 시스템 오디오 녹음에서 fairy 를 − 로 뺀다 | 없음 | 없음 |

`CLAUDE_CONFIG_DIR` 을 바꿔 쓰면 `~/.claude` 대신 그 폴더다.

## 문제 해결

**모델이나 도구 받기가 멈췄다, 계속 실패한다.**
받던 것은 이어 받는다. 페어리를 끄고 다시 켠 뒤 같은 단추를 누른다. 회사망처럼 GitHub, jsDelivr, unpkg, Hugging Face 가 막힌 곳에서는 받지 못한다. 프록시가 있으면 운영체제 프록시 설정(맥 시스템 설정 → 네트워크 → 프록시, 윈도우 설정 → 네트워크 및 인터넷 → 프록시)을 페어리가 따른다. 반쯤 받은 파일은 설정 → 데이터 → 저장 공간에서 지우고 다시 받을 수 있다.

**AI 프로그램이 회사 프록시 뒤에서 안 된다.**
AI 프로그램에는 페어리가 켜질 때 받은 `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS` 가 넘어간다. 맥은 Dock 이나 Finder 에서 켠 앱에 셸 설정의 환경 변수가 없어서, 터미널에서는 되는데 페어리에서 안 되면 그 AI 프로그램의 설정 파일에 프록시를 적는다.

**윈도우에서 SmartScreen 이 막는다.**
위 "윈도우" 2번. "추가 정보"를 눌러야 "실행"이 보인다.

**시작 안내를 다시 보고 싶다.**
설정 → 편의 → 시작 → **시작 안내 다시 보기**.

**설정을 처음으로 되돌리고 싶다.**
페어리를 끝내고 데이터 폴더(위 표)의 `settings.json` 만 지운 뒤 다시 켠다. 할 일과 페어리는 `jjakkung.db` 에 있어 그대로다. 모든 것을 처음부터 하려면 데이터 폴더를 통째로 다른 이름으로 바꿔 둔다(지우지 않으면 되돌릴 수 있다).

**설정 파일이 깨졌다고 페어리가 말한다.**
페어리는 깨진 설정 파일을 지우지 않고 `settings-broken-<시각>.json` 처럼 옆에 두고, 마지막으로 잘 읽은 복사본(`settings.json.bak`)으로 되살린다. 복사본이 없으면 기본값으로 시작한다. 옆에 둔 파일과 오래된 복사본은 설정 → 데이터 → 저장 공간에 보이고 지울 수 있다(30일이 지난 것은 새것 3개만 남기고 저절로 지운다).

**진단 기록은 어디 있나.**
데이터 폴더의 `logs/main.log`(1MB 가 넘으면 `main.old.log`). 질문, 답, 할 일과 일정 제목은 남기지 않는다. 문제가 생겨 도움을 청할 때는 설정 → 정보 → **도움 보내기**(설정 창에서 Cmd/Ctrl+Shift+H)가 앱 판, 운영체제, 켜진 기능, 서버 연결 상태와 함께 이 기록을 경로, 주소, 토큰, 이메일, 전화번호, 할 일과 메모와 일정 제목, 대화 내용까지 한 번 더 가린 글로 미리 보여 주고, "이대로 복사"나 "파일로 저장"으로 내가 직접 보낸다. 자동으로 올리지 않는다.

## 의견 보내기

메뉴 막대(윈도우는 작업 표시줄 오른쪽 아래)의 페어리 아이콘 → **의견 보내기**. "내 기록" 칸의 **기록 복사** 를 눌러 의견과 같이 붙여 보내 주면 된다. 복사한 글에는 날짜와 숫자만 들어 있다. 의견 보내기의 "문제 알리기"는 [fairy-releases 의 이슈](https://github.com/milcho0604/fairy-releases/issues)를 연다. 보안 문제는 공개 이슈 대신 [SECURITY.md](../SECURITY.md) 의 방법(fairy-releases 의 비공개 보안 알림)으로 알려 준다.
