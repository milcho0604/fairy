# 할 일을 구글 캘린더로 보내기 기획서

- 판: 2 (2026-11-08). 상태: 기획, 구현 전. 2판은 설계 검토(PR #301)를 반영했다(고친 곳에 `(2판)` 표시): 영구 삭제 뒤 남는 일정, 다시 허락 받기와 계정 바뀜, 보낸 기록 되돌리기 네 곳, 범위 밖 할 일, 시간대, 캘린더 둘 생김, 되돌리기 경로, 가져오기 id 머리.
- 정하는 것: 날짜가 있는 할 일을 사용자의 구글 캘린더에 한 방향으로 올려 휴대폰에서도 보게 하는 방법.
- 먼저 읽을 것: `docs/google-calendar.md`(지금 일정 보내기와 가져오기), `docs/sync-plan.md`(기기 간 동기화).
- 바뀌는 문서: `docs/google-calendar.md` 1절의 "후속 과제: 페어리 캘린더 만들기" 를 이 문서로 잇는다. 처리방침(`site/privacy`)과 구글 검수 설명도 고친다(10절).
- 나중 일: 휴대폰 일정 앱(플래니)과 잇기는 이슈 #300. 이 기능을 써 본 뒤에 본다.

## 1. 범위

- 하는 것: 끝내지 않은 할 일 가운데 날짜(`due`)가 있는 것을 구글 일정으로 올린다. 고치면 따라 고치고, 끝내거나 지우면 구글에서 지운다.
- 올릴 곳: 페어리가 새로 만든 "페어리 할 일" 캘린더(추천, 기본), 또는 사용자가 고른 기존 캘린더.
- 하지 않는 것:
  - 구글에서 고치거나 지운 것을 할 일로 되돌려 적지 않는다(한 방향). 다음에 페어리가 보낼 때 페어리 값으로 덮는다.
  - 단계(`todo_step`), 메모, 코인, 반복 규칙은 보내지 않는다.
  - 구글 Tasks 는 쓰지 않는다(새 권한이 필요하고, 휴대폰 캘린더 앱에 일정처럼 섞여 보이지 않는다).
- 켜는 조건: 구글 캘린더가 연결돼 있고, 사용자가 설정에서 직접 켠다. 기본은 꺼짐. 서버 계정과 동기화는 없어도 된다.

## 2. 사용자가 보는 것

1. 설정 > 구글 캘린더에 "할 일도 구글 캘린더에 올리기" 칸이 생긴다(연결돼 있을 때만).
2. 켜면 올릴 곳을 고르는 시트가 열린다.
   - "페어리 할 일 캘린더 새로 만들기 (추천)" 이 처음부터 골라져 있다.
   - "기존 캘린더에 올리기" 를 고르면 쓸 수 있는 캘린더 목록이 나온다. 일정 보내기 캘린더와 같은 것도 고를 수 있지만 그러면 일정과 섞인다는 한 줄을 보인다.
   - 시트 아래에 "할 일 제목과 날짜가 구글로 간다. 기기 간 동기화의 잠금과 상관없이 구글에서는 보인다" 를 적는다.
3. 새로 만들기를 고르면 구글 허락 화면이 한 번 더 열린다(3절). 허락하면 캘린더가 생기고, 지금 열린 할 일이 올라간다.
4. 휴대폰 구글 캘린더 앱에 "페어리 할 일" 캘린더가 보인다. 보기 싫으면 구글에서 그 캘린더만 끈다.
5. 설정 칸에는 올린 개수, 마지막으로 올린 때, 문제가 있으면 문제 한 줄이 보인다.

## 3. 권한

- 지금 받는 것: `calendar.events`, `calendar.calendarlist.readonly`. 기존 캘린더에 올리기는 이것만으로 된다. 새 권한이 없다.
- 새로 받는 것: `calendar.app.created`. (2판) 이 권한은 **캘린더를 만들고 지우는 데만** 쓴다(`calendars.insert`, `calendars.delete`). 그 캘린더에 일정을 쓰는 것은 이미 가진 `calendar.events` 로 한다. "새로 만들기" 를 고른 사람에게만, 그 순간에 묻는다.
- (2판) **다시 허락 받기는 따로 흐름(`grantAppScope`)으로 둔다.** 지금 `connect()` 는 성공하면 설정을 `push: true, pull: true, cals: null` 로 덮고(`src/main/gcal.ts` 533줄), 일정 칸을 풀면 받은 토큰을 돌려준다(525줄). 그 길을 타면 사용자가 꺼 둔 가져오기가 켜지고 캘린더 선택이 날아간다. 새 흐름은 이렇게 한다.
  - 세 권한을 한 번에 묻는다. 고른 칸만 주는 허락(granular consent)이 있으니, 받은 토큰의 `scope` 문자열로 판단한다.
  - `appScope` 는 `scope` 문자열에 `calendar.app.created` 가 **적혀 있을 때만** 참이다. 지금 `parseTokenResponse` 는 `scope` 가 비면 다 허락한 것으로 보는데(`gcal-auth.ts` 181줄), 이 칸에는 그 규칙을 쓰지 않는다.
  - 새 토큰이 `calendar.events` 와 `calendar.app.created` 를 둘 다 가졌고 같은 계정(아래)일 때만 지금 토큰을 새 토큰으로 바꾼다. 아니면 새 토큰만 버리고(돌려주기 하지 않는다. 구글의 돌려주기가 그 앱 허락 전체를 거둘 수 있어서) 지금 연결은 그대로 둔다. 설정(`push`, `pull`, `cals`)은 건드리지 않는다.
  - 새 권한 칸만 풀었으면 "기존 캘린더에 올리기" 로 안내한다. `scopeLost()` 는 부르지 않는다(일정 보낸 기록을 지우는 길이라서).
- (2판) **계정이 바뀌지 않았는지 확인한다.** 구글 계정 고르기 화면에서 다른 계정을 고를 수 있는데, 지금은 이메일 권한이 없어 알 수 없다.
  - 연결할 때 기본 캘린더의 id(구글 계정 메일과 같다)를 sha256 한 지문을 `google-calendar.json` 의 `account` 에 둔다. 값 자체는 저장하지 않는다.
  - 다시 허락 받은 뒤 새 토큰으로 캘린더 목록을 읽어 지문을 비교한다. 다르면 새 토큰을 버리고 "다른 구글 계정이야. 바꾸려면 연결을 끊고 다시 연결해 줘" 를 보인다.
  - 예전 연결(지문이 없음)은 다음 목록 읽기 때 채운다.
- 이미 연결한 사람은 이 기능을 켜기 전까지 다시 연결할 일이 없다.
- 구글 콘솔(사용자가 할 일): 동의 화면 Data access 에 `calendar.app.created` 를 더한다. 콘솔에 보이는 분류(민감한 범위인지)를 확인해 검수 설명에 맞춘다. 지금 게시 상태는 테스트(100명, 7일마다 연결이 끝남)라 검수 전에는 설명만 고쳐 둔다.

## 4. 캘린더는 계정마다 하나

- 만들 때: `calendars.insert` 로 summary 는 앱 언어에 따라 "페어리 할 일" 또는 "fairy to-dos", description 첫 줄에 표식 `fairy:todos:v1` 을 넣는다. 시간대는 이 컴퓨터 시간대.
- 표식으로 찾는다(이름은 사용자가 바꿀 수 있어서 쓰지 않는다). 캘린더 목록(`calendarList.list`)은 `description` 칸을 준다(구글 문서 확인). 목록 `fields`(`src/shared/gcal-cals.ts` 19줄)에 `description` 을 더하고, 표식이 있고 `accessRole` 이 owner 인 캘린더를 찾는다. 있으면 새로 만들지 않고 그것을 쓴다.
- (2판) **둘 생겼을 때 정본:** 두 컴퓨터가 동시에 켜면 둘 다 "없다" 를 보고 각자 만들 수 있다. 그래서 표식 캘린더가 여럿이면 **캘린더 id 가 사전순으로 가장 작은 것**을 정본으로 한다(기기마다 같은 답이 나온다).
  - 만든 직후 목록을 다시 읽어, 정본이 자기가 만든 것이 아니면 할 일을 올리기 전에 자기 것을 지운다.
  - 목록을 읽을 때마다(옵션 창, 15분 가져오기) 정본을 다시 정한다. 정본이 바뀌면 이미 올린 할 일을 `events.move` 로 옮긴다(6절).
  - 정본이 아닌 표식 캘린더가 남아 있으면 설정에 "페어리 할 일 캘린더가 둘 있어" 와 "남는 것 지우기" 를 보인다.
- 저장: `google-calendar.json` 에 `todos: { on, target: 'fairy' | 'pick', calendarId }` 를 더한다. (2판) `readPrefs` 는 아는 칸만 읽고 쓰므로(`gcal.ts` 75줄) `todos` 와 `account` 를 거기에 더한다. 안 더하면 저장할 때마다 사라진다. `made` 칸은 두지 않는다. 표식이 있으면 페어리가 만든 캘린더다(다른 컴퓨터가 만든 것도 지울 수 있다).
- 기기 간 동기화로 보내지 않는다. 구글 계정은 기기마다 다를 수 있기 때문이다.
- 사용자가 구글에서 캘린더를 지웠을 때: 보내기가 404 를 받으면 그 패스를 멈추고, 보낸 기록을 지우고, 설정에 "페어리 할 일 캘린더가 없어졌어" 와 "다시 만들기" 를 보인다. 저절로 다시 만들지 않는다(사용자가 일부러 지웠을 수 있다).
- 일정 보내기 대상과 일정 가져오기 목록에서 할 일 캘린더는 빠진다(7절).

## 5. 할 일을 구글 일정으로 바꾸기

| 할 일 | 구글 일정 |
|---|---|
| 제목 | summary 그대로 |
| 날짜만 (`dueMin` 없음) | 그날 종일 일정(`date`, 끝은 다음 날) |
| 날짜와 시각 | 그 시각부터 30분(`NO_END_MIN`, 일정과 같음), 이 컴퓨터 시간대 |
| 밀린 할 일 | 11절 2번에서 정한다 |
| 반복 | 지금 열린 회차 하나만. 끝내면 그 회차가 빠지고 새 회차(새 uid)가 올라간다 |
| 끝냄 (`done_at`) | 구글에서 지운다 |
| 끝냄 되돌리기 | 다시 올린다 |
| 지움 (`deleted_at`) | 구글에서 지운다 |
| 영구 삭제 | 구글에서 지운다 (2판, 6절 무덤) |
| 단계, 메모, 알림 | 보내지 않는다 (알림은 11절) |

- 표식: `extendedProperties.private` 에 `jjakkung: '1'`, `fairyKind: 'todo'` 를 붙인다. 가져오기가 되돌려 읽지 않게 하는 첫 장치다(7절).
- 구글 id: 할 일 uid 에서 정한다. (2판) `googleIdFromUid(uid, prefix)` 로 머리를 받게 바꾸고(지금은 `src/shared/sync-item.ts` 212줄의 `jjk` 고정), 할 일은 `jjt` 를 쓴다. 기존 호출처(`gcal-sync.ts` 71줄)와 시험을 같이 고친다. uid 에서 정해지므로 두 컴퓨터가 같은 할 일을 올려도 같은 id 다.
- (2판) **올리는 범위:** 아직 올린 적 없는 할 일은 날짜가 30일 전부터 그 뒤인 것만 올린다(처음 켤 때 오래 밀린 것이 쏟아지지 않게). **한 번 올린 할 일은 끝내거나 지울 때까지 둔다.** 날짜가 오래돼도 구글에서 빼지 않는다. 범위로 빼면 날짜를 옮길 때마다 휴대폰에서 사라졌다 생기기 때문이다.
- (2판) **끝냄 되돌리기 경로:** 끝낼 때 지우기는 `google_hash` 만 `deleted` 로 두고 `google_id`, `google_uid` 는 남긴다. 그래서 되돌리면 확인된 일정으로 보고 고치기(PATCH)부터 간다. 고치기 몸에 `status: 'confirmed'` 를 넣어 취소된 일정을 되살린다. 구글이 404, 410 을 주면 지금 코드처럼 무작위 새 id 로 새로 넣는다. 이 동작은 실제 구글에서 확인한다(12절).

## 6. 저장과 보내기

- 저장 파일 25판:
  - `todo` 에 `google_id`, `google_cal`, `google_hash`, `google_uid` 를 더한다(일정 표와 같은 이름과 뜻).
  - (2판) **무덤 표 `gcal_tomb`(kind, google_id, google_cal, at)** 를 둔다. 할 일 행이 영구 삭제되면 `google_id` 도 사라져 구글 일정을 지울 근거가 없어진다. 영구 삭제 길은 넷이다: `TodoStore.purge`, `emptyTrash`, `purgeExpired`(30일), 다른 기기의 지움 표식을 적용하는 `src/main/sync/rows.ts` 의 `purgeRow`. 이 넷이 행을 지우기 전에, `google_id` 가 있고 `google_hash` 가 `deleted` 가 아닌 행을 무덤에 옮긴다. 보내기는 무덤 줄을 구글에서 지우고(404 도 지운 것으로) 줄을 뺀다. 연결을 끊으면 무덤도 비운다.
- 동기화: 네 칸은 기기 간 동기화에서 맞추지 않는 칸에 넣는다(`src/shared/sync-fields.ts` 의 todo 제외 목록). (2판) 검토에서 확인한 것: 트리거가 `after update of <맞추는 칸>` 이라 네 칸만 바뀐 행은 `sync_outbox` 에 들어가지 않는다. 제외 목록에 넣지 않으면 `sync-triggers.test.ts` 가 실패하므로 함께 고친다.
- 보낼 것 고르기: 따로 줄을 두지 않고 저장 파일에서 고른다(일정과 같은 방식). (2판) 일정의 쪽 나눔(시작 시각 순 200개)은 할 일에 맞지 않으므로 질의를 새로 짠다.
  - 올릴 것: 끝내지 않았고 지우지 않았고 날짜가 있고, (올린 적 있음 또는 30일 범위 안), 지문이 다름.
  - 지울 것: 끝냈거나 지웠거나 날짜를 뺐는데 `google_id` 가 있고 `google_hash` 가 `deleted` 가 아님. 그리고 무덤 줄 전부.
  - 지문은 구글로 보낼 몸과 이 컴퓨터 시간대로 만든다.
- 보내기: `gcal-sync.ts` 의 한 차례 보내기(`applyOp`, `GcalBackoff`, `eventsPath`)를 할 일 쪽 저장에도 쓸 수 있게 저장 쪽을 인터페이스로 뺀다. 일정과 할 일은 같은 순서 안에서 차례로 돌린다(동시에 돌리지 않는다).
- 언제: 할 일이 바뀌면 1.5초 뒤, 아니면 5분마다(일정과 같다). 펫 MCP 서버(다른 프로세스)가 고친 할 일도 저장 파일에서 고르므로 5분 안에 따라간다.
- 올릴 곳을 바꾸면(정본 바뀜 포함): 이미 올린 할 일은 `events.move` 로 옮긴다. 옛 캘린더를 쓸 수 없으면 새로 넣는다(일정과 같다).
- (2판) **보낸 기록 되돌리기:** 지금 `resetSent` 는 일정 표만 고치고 네 곳에서 불린다(`gcal.ts` 의 연결 끝남 248줄, `scopeLost` 303줄, 연결 끊기 568줄, 백업 가져오기 687줄). 네 곳 모두 할 일 쪽 `resetSent` 도 부른다. 연결 끊기에서는 `todos.calendarId` 와 `account` 도 비운다. 연결 끝남(7일 만료)에서는 둘을 남기고 다시 연결할 때 3절의 계정 지문으로 확인한다. 다르면 그때 비운다.

## 7. 가져오기와 겹침

- 할 일 캘린더는 가져오기 목록(`pullCals`)과 일정 보내기 대상에서 뺀다. 캘린더 옵션 창에도 그 줄을 "할 일 전용" 으로 회색 처리한다.
- 사용자가 기존 캘린더(예: 기본 캘린더)에 할 일을 올리고 그 캘린더를 가져오기로도 읽으면, 올린 할 일이 일정으로 되돌아올 수 있다. 막는 장치는 세 가지다.
  - `isFromFairy()` 의 표식 검사(`jjakkung: '1'`).
  - (2판) id 머리 검사(`gcal-pull.ts` 66줄)는 지금 `jjk` 만 본다. 머리 목록(`jjk`, `jjt`)으로 바꾼다. 보내는 중 대답을 못 받아 `google_uid` 가 없는 일정도 이것으로 걸린다.
  - `sentUids()` 가 할 일 표의 `google_id`, `google_uid` 도 모은다(표식이 지워진 경우).
- 시험: 기본 캘린더에 할 일을 올리고 같은 캘린더를 가져와도 일정이 하나도 생기지 않는다.

## 8. 기기 간 동기화와 함께

- 같은 구글 계정의 두 컴퓨터: 4절 정본 규칙으로 같은 캘린더를 쓰고, 5절 id 가 uid 에서 정해지므로 늦게 보낸 쪽은 409 를 받고 고치기로 간다. 겹치지 않는다.
- (2판) 다른 기기에서 동기화로 온 할 일은 이 기기에 구글 칸이 비어 있어, 기기마다 한 번 넣기(409) 뒤 고치기가 나간다. 할 일 하나에 부르기 두 번이고 받아들인다.
- (2판) 두 컴퓨터의 시간대가 다르면(출장 등) 같은 시각 할 일(`dueMin` 은 그 기기의 현지 시계 분)을 서로 다른 순간으로 보낸다. 구글에는 마지막으로 보낸 기기의 시간대 기준이 남는다. 지문이 기기마다 달라 서로 덮을 수 있지만 할 일을 고칠 때만 일어난다. 첫 판은 "보낸 기기의 시간대 기준" 으로 두고 설정 도움말에 적는다.
- 한 컴퓨터에서 끝낸 할 일: 동기화로 다른 기기에도 끝냄이 오면 그 기기의 지움 요청은 404 라 지운 것으로 친다.
- 다른 구글 계정의 두 컴퓨터: 각자 자기 계정에 캘린더를 만든다. 서로 상관없다.
- 동기화를 켜지 않은 두 컴퓨터: 할 일 uid 가 서로 달라 같은 캘린더에 각자 것이 올라간다. 정상이다.

## 9. 끄기, 끊기, 지우기

- 이 칸을 끄면 보내기만 멈추고 구글의 일정과 캘린더는 둔다. 설정에 "구글에 올린 할 일도 지우기" 단추를 따로 둔다.
  - 표식 캘린더면 `calendars.delete` 로 캘린더째 지운다.
  - 기존 캘린더면 올린 할 일만 하나씩 지운다.
  - 둘 다 확인을 한 번 받는다(앱 안 시트, OS 창 아님).
- 구글 연결 끊기, 연결 끝남(7일 만료), 백업 가져오기: 6절 "보낸 기록 되돌리기" 대로 한다. 다시 연결하면 같은 id 로 넣기부터 해서 같은 계정이면 409 다음 고치기로 겹치지 않는다.

## 10. 개인정보

- 구글로 가는 것: 할 일 제목, 날짜, 시각. 단계, 메모, 코인, 반복 규칙은 가지 않는다.
- 동기화는 E2E 로 잠그지만 이 기능은 사용자가 고른 구글 캘린더에 평문으로 쓴다. 켜는 시트(2절)에 그렇게 적는다.
- 계정 지문(3절)은 기본 캘린더 id 의 sha256 이고 이 컴퓨터에만 둔다.
- 처리방침 `site/privacy`: 구글 캘린더 항목에 "사용자가 켜면 날짜가 있는 할 일의 제목과 날짜, 시각을 사용자가 고른 캘린더 또는 페어리가 만든 캘린더에 쓴다" 를 더한다(ko, en). 시행일은 바꾼 날.
- 구글 검수 설명(`docs/google-calendar.md` 2절의 영어 글)에 세 번째 쓰임새와 `calendar.app.created`(캘린더 만들기와 지우기에만)를 더하고, 시연 영상 항목에 "할 일 캘린더 만들기와 할 일이 올라간 모습" 을 더한다.

## 11. 사용자가 정할 것 (추천을 먼저)

1. 구글 알림: **넣지 않는다 (추천)**. 페어리가 컴퓨터에서 이미 알려서, 넣으면 휴대폰과 컴퓨터에서 두 번 울린다. 넣는다면 할 일의 알림 시각을 그대로 쓴다.
2. (2판) 밀린 할 일 위치: **오늘 종일 일정으로 옮긴다 (추천)**. 원래 날짜에 두면 휴대폰의 오늘 화면에 안 보여 "휴대폰에서 보기" 목적과 어긋난다. 대가는 밀린 할 일마다 하루 한 번 고치기(부르기 한 번)이고, 지문에 오늘 날짜가 들어가 저절로 된다. 시각이 있던 할 일도 오늘 종일로 옮긴다(지난 시각에 두면 이미 지나간 일정으로 보인다). 제목은 바꾸지 않는다.
3. 날짜만 있는 할 일: **종일 일정으로 올린다 (추천)**. 페어리 전용 캘린더라 일정을 덮지 않는다.
4. 끌 때: **보내기만 멈추고 지우기는 따로 단추 (추천)**.

## 12. 시험

- 단위(네트워크 흉내):
  - 바꾸기 표(5절)의 줄마다
  - 지문이 같으면 안 보냄
  - 반복 회차 넘어감
  - 끝냄과 되돌리기(PATCH 먼저)
  - 한 번 올린 할 일은 30일이 지나도 남음, 처음 켤 때 30일 넘게 밀린 것은 안 올라감
  - (2판) 영구 삭제 네 길(`purge`, `emptyTrash`, `purgeExpired`, 동기화 `purgeRow`) 뒤 무덤 줄이 생기고 구글 지우기가 나감
  - 캘린더 404 와 다시 만들기 안내
  - 표식 캘린더 찾기(0개, 1개, 2개, owner 아님), 두 기기가 같은 정본을 고름, 만든 직후 더 작은 id 가 있으면 자기 것을 지움
  - (2판) 다시 허락: 새 권한 칸만 풂, 일정 칸을 풂, 다른 계정을 고름, `scope` 가 빔. 네 경우 모두 지금 토큰과 설정(`push`, `pull`, `cals`)과 일정 보낸 기록이 그대로
  - (2판) `resetSent` 네 곳에서 할 일 쪽도 되돌려짐, `todos` 와 `account` 가 설정 저장 뒤에도 남음
- 동기화: 구글 칸 네 개만 바뀐 행이 `sync_outbox` 에 들어가지 않음. 두 기기 흉내(`scripts/dev/sync-two.mjs` 방식)에서 같은 할 일이 같은 구글 id.
- 가져오기: 7절 시험, `jjt` 머리이고 표식이 없는 일정도 걸러짐.
- 실제 구글(사람이 한 번, 테스트 계정):
  - 새 권한 허락 화면과 고른 칸만 주기
  - 캘린더 만들기, 휴대폰 앱에 보이는지
  - 끝낸 뒤 되돌리기(취소된 일정에 `status: confirmed` 고치기)
  - 캘린더째 지우기
- 화면: 설정 칸과 시트를 밝음, 어두움, 좁은 폭, ko, en 으로 찍는다.
