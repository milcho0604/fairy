# 설정 검색·탭 스크롤·시작 안내 (#149, #144)

요청받은 세 항목만 처리한다. 두 이슈의 다른 하위 업무는 포함하지 않는다.

## 바뀐 동작

- 설정 검색은 실제 표시된 동작 이름에 동의어를 붙인다. 자동 실행/시작프로그램/autostart, 초기화/reset, 삭제/delete, 종료/quit 등을 한국어·영어 화면에서 찾을 수 있다. `기본 모델`처럼 동작이 아닌 표현은 초기화로 연결하지 않는다. 영어 단축키의 Reset 단추에는 명시적 검색 메타데이터도 붙인다.
- 설정 창의 여섯 탭은 각각 스크롤 위치를 기억한다. 탭을 숨기고 새 탭을 보인 뒤 복원하므로 짧은 탭의 높이에 잘리지 않는다. 마우스, 방향키, Cmd/Ctrl+숫자 모두 적용한다. 검색 위치는 따로 관리하며 검색 지우기·Esc·검색 중 탭 선택은 원래 탭 위치를 복원한다. 기억 범위는 열린 설정 창이다.
- 시작 안내 높이는 한국어 580px, 영어 664px로 정한다. 작업 영역이 작으면 그 크기 안으로 줄이고 본문만 스크롤한다. 아래 이전/다음/시작 단추는 계속 보인다. 안내가 열린 동안 언어를 바꾸면 창 높이도 새 언어에 맞춰 바꾼다.

## 변경 전후 실측

이전 빌드와 수정 빌드를 같은 빈 사용자 데이터 조건으로 CDP에서 측정했다. 단위는 CSS px다.

| 언어/쪽 | 변경 전 본문 높이 / 내용 높이 | 변경 후 본문 높이 / 내용 높이 |
| --- | --- | --- |
| 한국어 첫 쪽 | 447 / 451 | 467 / 467 |
| 한국어 마지막 쪽 | 447 / 463 | 467 / 467 |
| 영어 첫 쪽 | 447 / 518 | 551 / 551 |
| 영어 마지막 쪽 | 447 / 548 | 551 / 551 |

한국어 첫 쪽만 보면 4px 증가로 해결되지만 영어와 마지막 안내는 더 넘쳤으므로 언어별로 높이를 맞췄다.
360×500 작업 영역을 주입한 시험에서는 창이 처음부터 360×500으로 열리고, 본문을 내려 마지막 설정 안내까지 읽을 수 있음을 확인했다.

## 검증 (2026-10-27)

- `npm run check`: 타입 검사, lint, 단위 시험 2,351개 통과
- `npm run build`: 통과
- `settings-polish.mjs`: 한국어 67개, 영어 67개 검사 통과
- 폭 320/440/760에서 여섯 탭의 서로 다른 위치 복원, 방향키와 Cmd/Ctrl+3, 검색 시작·종료·Esc 복귀
- 실제 화면에서 자동 실행/autostart/초기화/삭제 검색 결과 확인
- 기본 크기에서 안내 다섯 쪽 모두 불필요한 스크롤 없음. 열린 안내에서 한국어↔영어를 바꿀 때 창 높이가 함께 바뀌는 것도 확인
- 작은 작업 영역에서 버튼과 마지막 안내 접근
- 화면은 CDP로 촬영하고 확인. 시험 프로세스와 임시 데이터 정리 완료

```bash
npm run check
npm run build
OUT=/tmp/fairy-settings LANG_UNDER_TEST=ko node scripts/dev/settings-polish.mjs
OUT=/tmp/fairy-settings LANG_UNDER_TEST=en node scripts/dev/settings-polish.mjs
```

이전 빌드에서 `BASELINE=1`을 주면 시작 안내 변경 전 측정과 화면만 남긴다.
결과 JSON·PNG·로그는 OUT에 저장한다. 앱은 `JJ_NO_FOCUS=1`, 빈 `JJ_USER_DATA`, 임시 HOME으로
내장 화면에 숨겨 띄우며 실제 마우스와 키보드를 사용하지 않는다.
