개인정보처리방침

페어리는 내 컴퓨터에서 도는 데스크톱 앱이에요. 서버 기능은 여러분이 켤 때만 써요. 무엇을 어디에 두고, 무엇이 언제 어디로 나가는지 있는 그대로 적었어요.

시행일 2026년 10월 30일

2026년 10월 30일 개정: 친구별 일정 제목 공유, 펫 놀러 가기, 쪽지함이 서버 백업에 든다는 항목을 더했어요.

짧게 읽기

어린이도 읽기 쉽게 줄였어요. 자세한 내용은 아래에 있어요.

  • 할 일, 메모, 일정, 일기, 페어리는 내 컴퓨터에 있어요. 만든 사람은 보지 않아요.
  • 서버 기능(계정, 서버 코인, 쿠폰, 친구와 선물, 서버 백업, 채팅 이용권)은 켜고 싶을 때만 켜요. 켜기 전에 나이를 한 번 물어요. 기능은 순서대로 열려요. 아직 열리지 않은 기능도 있어요.
  • 만 14세보다 어리면 서버 기능을 쓰지 않아요. 앱은 그대로 다 쓸 수 있고, 서버로는 아무것도 가지 않아요.
  • 서버 기능을 켜도 실명, 이메일, 전화번호, 생일은 받지 않아요. 계정을 알아보는 번호, 내가 정한 닉네임, 코인 기록 같은 것만 받아요.
  • 채팅 이용권은 만 18세 이상만 써요. 처음 쓸 때 안내를 읽고 "알겠어, 채팅 이용권 쓰기"를 눌러야 질문이 가요. 질문은 Claude를 만든 미국 회사 Anthropic으로 가고, Anthropic은 정책상 최대 30일 보관해요. 페어리 서버는 대화 내용을 저장하지 않아요. 싫으면 이용권 대신 내 컴퓨터의 AI로 대화하면 돼요.
  • 할 일, 메모, 일정은 "서버에 백업 올리기"를 직접 누를 때만 서버로 가요. 구글에서 읽어 온 일정도 그 파일에 들어가요. 파일은 암호화해 두고, 그 백업을 올린 나만 되살릴 때 써요.
  • 설정에서 "서버 계정 지우기"를 누르면 서버에 있던 내 것이 바로 지워져요. 운영자가 장애에 대비해 만드는 데이터베이스 사본에는 최대 7일 남을 수 있어요.
  • 친구와 선물, 바쁜 시간 보여 주기는 열리는 대로 쓸 수 있어요. 바쁜 시간과 제목 보여 주기, 펫 놀러 가기는 처음에 꺼져 있어요.
  • 모르는 말이 있으면 어른과 같이 읽거나 아래 문의로 물어보세요.

이 방침이 다루는 것

이 방침은 데스크톱 앱 페어리(영문 이름 fairy)과 이 사이트 fairy.moilga.com에 적용돼요. 서버 기능을 켰을 때 쓰는 페어리 서버(fairy-api.moilga.com)에도 적용돼요. 페어리는 milcho0604가 개인으로 만드는 MIT 라이선스 오픈 소스 앱이에요. 서버 기능을 켜지 않으면 만든 사람은 여러분의 데이터를 받지도 보지도 않아요. 서버 기능을 켰을 때 받는 개인정보는 milcho0604가 직접 처리해요.

서버 기능을 쓸 때의 약속은 이용약관에 적었어요.

내 컴퓨터에 저장하는 것

아래는 모두 이 컴퓨터의 페어리 데이터 폴더에만 저장돼요.

  • 할 일, 메모, 일정, 일기, 코인, 페어리 상태와 페어리가 기억하는 것, 설정 (SQLite 저장 파일과 설정 파일)
  • 채팅 창의 최근 대화 40개. 붙인 그림은 저장하지 않아요
  • 구글 캘린더 연결 토큰과, 넣었다면 Hugging Face 토큰을 저장해요. 나만 읽을 수 있는 파일에 두고, 운영체제 열쇠를 쓸 수 있으면 암호화해요.
    자세히 보기나만 읽을 수 있는 파일(권한 0600)에 두고, 운영체제 열쇠(맥 키체인, 윈도우 DPAPI, 리눅스 libsecret 등)를 쓸 수 있으면 암호화해요.
  • 진단 기록(logs 폴더, 합쳐서 2MB 이하). 질문, 답, 할 일과 일정 제목은 남기지 않고 파일 경로 속 사용자 이름은 가려요
  • 받아 둔 AI 모델과 도구, 모델 목록 사본
  • "같이 보기"로 찍은 화면은 디스크에 저장하지 않아요
  • 서버 기능을 켰다면: 고른 나이 답, 서버가 준 기기 토큰과 로그인 세션 토큰(운영체제 열쇠로 암호화해 둬요), 아직 서버로 보내지 않은 코인 기록

데이터 폴더 위치

  • macOS ~/Library/Application Support/fairy
  • Windows %APPDATA%\fairy
  • Linux ~/.config/fairy

정보를 쓰는 곳

저장한 정보는 알림, 페어리의 말과 행동, 고른 AI와의 대화처럼 여러분이 쓰는 기능을 이 컴퓨터에서 돌리는 데만 써요. 광고, 분석, 프로필 만들기에는 쓰지 않아요.

컴퓨터 밖으로 나가는 것

그 기능을 직접 쓸 때만 나가요. 아래 "서버 기능을 켰을 때"에 적은 것 말고는 페어리 서버를 거치지 않고 이 컴퓨터에서 바로 그곳으로 가요.

  • AI 대화, 같이 보기, 메모와 일기 다듬기: 질문, 고른 화면이나 그림, 그 메모나 일기 글을 여러분이 고른 AI 프로그램에 넘겨요. 프로그램은 Claude Code, Codex, Cursor, Gemini CLI, 직접 추가한 프로그램 중 하나예요. 그 프로그램이 자기 회사(Anthropic, OpenAI, Cursor, Google 등)로 보내요. 거기서부터는 그 회사의 약관과 개인정보 정책을 따라요. 페어리 이름과 성격도 같이 가요. "내 할 일 같이 보내기"나 "페어리 도구 쓰기"를 켜면 할 일과 일정도 갈 수 있어요. 둘 다 처음에는 꺼져 있어요. 구글 캘린더에서 읽어 온 일정은 "AI가 구글 일정도 볼 수 있게"까지 켜야 가요. 무료 AI(이 컴퓨터에서 도는 모델)를 고르면 아무것도 나가지 않아요.
  • AI 일러스트 (무료 서버): 고른 사진과 바라는 점을 Hugging Face의 무료 그림 서버(다른 사람이 운영하는 Space)로 보내요. Hugging Face 토큰을 넣었다면 그 서버에만 같이 보내요.
  • 구글 캘린더 연결: 아래 "구글 캘린더" 항목에 따로 적었어요.
  • 캘린더 가져오기: 여러분이 넣은 .ics 주소에서 일정을 받아 오기만 해요.
  • 업데이트 확인과 자동 업데이트, 모델 목록, 페어리 갤러리: GitHub의 공개 저장소 milcho0604/fairy-releases에서 받아요. 앱 이름과 버전 말고는 알리지 않아요.
  • 모델과 도구 받기: 무료 AI나 배경 지우기 같은 기능을 처음 쓸 때 파일을 받아요. 받는 곳은 GitHub, Hugging Face, npm 저장소, jsDelivr, unpkg예요. 받기만 하고 보내는 것은 없어요.
  • 공지 받기: 앱을 켤 때와 하루 몇 번 이 사이트(fairy.moilga.com)에서 공지 파일을 받아요(이벤트 목록이 생기면 그 파일도요). 할 일 같은 내 데이터는 보내지 않아요. 요청에는 앱 이름과 버전, IP 주소 같은 접속 정보가 따라가요. 서버 기능을 켜지 않았거나 만 14세 미만이어도 똑같이 받아요.
  • 어느 곳이든 연결하면 그 서버는 여러분의 IP 주소 같은 접속 정보를 보게 돼요.
  • 사용 통계, 광고, 오류 자동 보고는 없어요. 진단 기록도 저절로 나가지 않아요. 의견을 보낼 때 여러분이 직접 복사하거나 저장해서 붙일 때만 나가요.

서버 기능을 켰을 때

서버 기능은 기기 계정, 서버에 두는 코인과 산 물건, 로그인, 쿠폰, 이벤트 선물, 친구와 선물, 서버 백업, 채팅 이용권이에요. 앱은 처음 켤 때 서버에 아무것도 보내지 않아요. 이 기능을 처음 쓰려 할 때 나이를 한 번 물어요. 답은 "만 14세 미만", "만 14세 이상 18세 미만", "만 18세 이상" 중 하나예요. 만 14세 이상이고 여러분이 켠 경우에만 서버와 주고받아요. 기능은 순서대로 열려요. 열린 계정부터 해당하고, 아래 내용은 그 기능이 열린 뒤 여러분이 쓸 때부터 적용돼요.

서버에 보내고 두는 것

  • 나이 구분: "만 14세 이상"인지 "만 18세 이상"인지만 보내요. 생년월일과 정확한 나이는 보내지 않고, 고른 답은 앱에만 둬요. 서버 기능과 채팅 이용권을 쓸 수 있는지 가리는 데 써요.
  • 기기 계정: 서버 기능을 켜면 서버가 이름 없는 계정을 만들어요. 이 기기에 열쇠 토큰도 줘요. 서버에는 그 토큰을 알아볼 표식만 둬요. 원래 값으로 되돌릴 수 없어요.
    자세히 보기서버에는 그 토큰의 해시(원래 값으로 되돌릴 수 없게 바꾼 값)만 둬요. 계정에는 서버가 붙인 무작위 기기 코드(F-XXXX-XXXX 모양)가 있어요. 정했다면 닉네임(2~12자, 실명이 아니어도 돼요)도 있어요. 만든 때, 마지막으로 쓴 때(하루에 한 번만 적어요), 앱 판 번호도 남아요. 기기 코드는 운영자가 선물을 줄 계정을 찾을 때와 친구를 맺을 때 써요. 마지막으로 쓴 때는 오래 안 쓴 계정을 지우는 데 써요. 앱 판 번호는 낡은 앱에 업데이트를 안내하는 데 써요.
  • 로그인: 구글 로그인을 이으면 구글이 알려 주는 계정 고유 번호만 받아요. 이름, 이메일, 사진은 받지 않아요. 구글 비밀번호는 페어리도 서버도 보지 않아요.
    자세히 보기구글 로그인을 이으면 구글이 알려 주는 계정 고유 번호(sub)만 받아요. 구글에 요청하는 범위는 openid 하나라 이름, 이메일, 사진은 받지 않아요. 구글 비밀번호는 페어리도 서버도 보지 않아요. 다른 기기에서도 같은 사람인지 알아보고 코인, 산 물건, 이용권을 되찾는 데 써요. 카카오 로그인은 아직 열지 않았어요. 열리면 카카오 회원번호 하나만 받고 이름과 이메일은 받지 않아요.
  • 코인과 산 물건 기록: 코인을 언제, 얼마나, 무슨 까닭으로 벌고 썼는지 보내요. 출석, 할 일, 집중 같은 까닭이에요. 산 물건(집 단계, 집 모양, 장난감)과 개수도 보내요. 받은 이벤트 선물, 쓴 쿠폰, 쪽지함의 운영자 쪽지와 선물도 있어요. 할 일 제목이나 내용은 보내지 않아요. 코인 장부를 지키고, 같은 선물을 두 번 받지 않게 하는 데 써요. 기기를 바꿔도 이어 쓰는 데도 써요.
  • 채팅 이용권 사용량: 남은 이용권 수와, 질문마다 쓴 토큰 수와 추정 비용, 쓴 때와 모델 이름 같은 숫자만 둬요. 이용권을 차감하고 하루와 한 달 상한을 지키는 데 써요. 서버 계정을 지우면 계정과의 연결을 지우고, 계정 번호 없는 숫자만 한 달 상한 계산에 남아요. 이 숫자를 지우는 때는 아직 정하지 않았어요.
  • 채팅 이용권의 질문과 답: 서버에 저장하지 않아요. 서버는 질문을 Anthropic에 넘기고 답을 돌려줄 뿐이에요. 답은 사람이 아니라 Anthropic의 생성형 AI(Claude)가 만들고, 대화 창에는 늘 "AI와 대화 중"이라고 보여요.
  • 서버 백업 (누를 때만): 로그인한 뒤 설정 → 데이터와 계정에서 "서버에 백업 올리기"를 직접 누를 때만 올려요. 올리는 파일은 내 컴퓨터에 저장하는 백업과 같아요.
    자세히 보기올리는 파일은 내 컴퓨터에 저장하는 백업과 같고, 데이터 파일 전체(jjakkung.db)가 들어 있어요. 할 일, 메모, 일정, 코인 기록, 페어리 상태와 성장, 산 물건, 설정, 캐릭터 그림이 들어 있어요. 백업 파일에는 일기와 페어리가 기억하는 것, 쪽지함(페어리 편지, 받은 쪽지와 공지)도 들어 있어요. 일정에는 구글 캘린더에서 읽어 온 일정(제목, 시작과 끝 시각, 구글 일정 식별자, 캘린더 id)과 .ics로 가져온 일정이 들어가요. 구글 로그인 토큰, 받은 모델, 대화 기록은 들어가지 않아요. 파일은 서버 디스크에 AES-256-GCM으로 암호화해 둬요. 암호 키는 서버 설정 파일에 있고 운영자가 관리해요. 그래서 운영자는 기술적으로 풀 수 있어요. 하지만 백업을 올린 사람이 되살리려고 내려받을 때 말고는 풀지 않아요. 열어 보거나 다른 데 쓰지도 않아요. 건강이나 가족 이야기 같은 민감한 내용이 들어 있을 수 있어서, 처음 올릴 때 따로 동의를 받아요. 동의하지 않으면 내 컴퓨터에 저장한 백업 파일을 쓰면 돼요.
  • 신고한 대화: 채팅 이용권 답에 붙은 "신고" 단추를 누르면, 이 질문과 답을 운영자에게 보낼지 묻는 창이 떠요. 무엇이 가는지 보여 주고 "보내기"를 눌렀을 때만 그 질문과 답이 운영자 화면에 올라가요. 누르지 않으면 아무것도 가지 않아요. 안전하지 않은 답을 살피고 막는 데 써요. 운영자만 보고, 받은 날부터 30일 뒤 지워요.
  • 운영 기록: 운영자가 선물을 주거나 계정을 합친 일 같은 운영 작업을 누가, 언제, 무엇을 했는지 남겨요.
  • 서버 계정을 지워도 남는 것: 첫 로그인 이용권 선물과 하루 질문 수를 세려고 쓰는 값이 남아요. 이름이나 이메일은 아니에요. 하지만 완전히 익명도 아니에요. 같은 로그인으로 선물을 또 받지 못하게 하려고 계정을 지운 뒤에도 남아요. 선물 기록은 1년, 하루 질문 수 기록은 이틀 뒤 지워요.
    자세히 보기첫 로그인 이용권 선물과 하루 질문 수를 세려고, 로그인 번호를 서버 비밀 키로 섞은 값(HMAC)을 계정과 따로 둬요. 비밀 키가 있으면 같은 로그인인지 다시 맞춰 볼 수 있는 값이에요. 그래서 이름이나 이메일은 아니지만 완전히 익명은 아니에요. 지운 뒤 같은 로그인으로 선물을 또 받는 것을 막으려는 거라 계정을 지워도 남아요. 선물 기록은 1년, 하루 질문 수 기록은 이틀 뒤 지워요.
  • 친구와 선물 (열리는 대로): 만 14세 이상이 로그인했을 때만 쓰고, 같은 나이 구분끼리만 친구가 돼요. 친구에게는 내 닉네임과 기기 코드가 보여요. 서버에는 친구 관계, 신청, 차단한 사람이 계정 번호로만 남아요. 선물(코인, 채팅 이용권)은 서버를 거쳐 친구의 쪽지함으로 가고, 보낸 때와 양이 기록돼요. 친구가 30일 안에 열지 않거나 서버 계정을 지우면 나에게 돌아와요. 바쁜 시간 보여 주기는 처음에 꺼져 있고 친구마다 내가 켜요. 켜면 페어리에 직접 넣은 일정의 앞으로 14일 시작과 끝 시각만 올라가요. 제목은 아래 스위치를 켠 친구에게만 가요. 장소, 메모, 참석자는 보내지 않고, 구글에서 읽어 온 일정과 .ics로 가져온 일정도 보내지 않아요. 친구 신청은 14일 안에 받지 않으면 만료돼요. 끄거나 친구를 끊거나 로그아웃하면 서버에서 바로 지워요.
  • 친구별 일정 제목 공유 (기본 꺼짐): 바쁜 시간 보여 주기를 켠 친구마다 따로 켤 수 있어요. 켜면 페어리에 직접 넣은 공개 일정의 제목(80자까지)과 시간대만 올라가요. 장소, 메모, 참석자는 받지 않아요. 구글에서 읽어 온 일정, .ics로 가져온 일정, 비공개 일정의 제목은 보내지 않아요. 제목은 나와 그 친구가 둘 다 만 18세 이상이고 바쁜 시간 보여 주기가 켜져 있을 때만 보여요. 만 14~17세는 제목을 켜지도 보지도 못해요.
    자세히 보기제목 보여 주기를 끄거나, 제목을 보던 친구가 없어지거나, 바쁜 시간 보여 주기를 끄면 제목은 바로 지워요. 로그아웃하거나, 친구를 끊거나, 차단하면 바로 지워요. 나이 구분이 바뀌어 한쪽이 만 18세 미만이 되면 바로 지워요. 계정을 지우거나 합쳐도 바로 지워요. 일정이 끝나면 그 제목은 1시간 안에 지우고, 앞으로 14일치만 둬요.
  • 펫 놀러 가기 (기본 꺼짐): 친구마다 내가 켜요. 기본은 꺼져 있고, 친구도 켜야 서로 보여요. 만 14~17세끼리, 성인끼리만 해요. 서버에는 펫 종류(앱에 든 기본 종류), 펫 이름(2~12자), 네 발로 서 있는지 여부, 올린 때만 둬요. 친구에게는 펫 종류, 펫 이름, 내 닉네임만 보여요. 사진, 직접 만든 그림, 펫 파일은 보내지 않고 기본 모양 대역으로 보여요. 서버는 방문이 있었는지 기록하지 않아요. 손님 펫이 언제 올지는 받는 사람 컴퓨터가 정해요. 끄거나, 켠 친구가 없어지거나(끊기, 차단, 나이 구분 변경), 로그아웃하거나, 계정을 지우거나 합치면 바로 지워요. 앱이 14일 동안 올리지 않아도 지워요. 친구가 끄거나 끊거나 차단하면 서버는 바로 멈추고, 와 있던 손님 펫은 1분 안에 돌아가요.

받지 않는 것

  • 실명, 이메일, 전화번호, 생년월일. 닉네임은 내가 정하는 별명이라 실명이 아니어도 돼요.
  • 서버 프로그램은 IP 주소를 데이터베이스나 파일에 저장하지 않아요. 너무 많은 요청을 막는 데 IP 주소를 쓰지만, 되돌릴 수 없는 값으로 바꿔요. 그 값은 메모리에만 잠시 둬요. 다만 Cloudflare를 지나는 동안은 Cloudflare가 IP 주소를 봐요.
    자세히 보기너무 많은 요청을 막으려고(레이트리밋) IP 주소를 되돌릴 수 없게 바꾼 값을 메모리에만 잠시 둬요.
  • 할 일, 메모, 일정을 서버에 늘 맞춰 두지 않아요. 서버 백업을 직접 누를 때(저장 파일 전체가 가요), 그리고 바쁜 시간 보여 주기를 켠 친구에게는 일정의 시작과 끝 시각만 가요. 제목 보여 주기를 켠 친구에게만 제목도 가요. 채팅 기록은 서버로 가지 않아요.
  • 광고, 마케팅, 방문 분석에 쓰지 않고, 그런 동의도 받지 않아요.
  • 만 14세 미만이거나 서버 계정을 켜지 않으면 서버로 아무것도 보내지 않아요. 코인은 이 컴퓨터의 장부에만 있어요.

서버 기능에 꼭 필요한 정보는 그 서비스를 드리려고 처리해요. 서버 백업과 신고한 대화는 건강이나 가족 이야기 같은 민감한 내용이 들어 있을 수 있어서 따로 동의를 받은 뒤에만 처리해요. 따로 동의하지 않아도 다른 기능은 그대로 쓸 수 있어요.

설정 → 비서 → "구글 캘린더"에서 구글 계정을 연결할 수 있어요. 연결하면 페어리에서 넣은 일정을 여러분의 구글 캘린더에도 넣어요. 고른 캘린더들에 원래 있던 일정은 페어리에 보여 줘요. 연결은 선택이고, 연결하지 않으면 페어리는 구글 API를 쓰지 않아요.

  • 요청하는 권한: 두 가지뿐이에요. 하나는 일정 보기와 쓰기(https://www.googleapis.com/auth/calendar.events)예요. 다른 하나는 캘린더 목록 보기(https://www.googleapis.com/auth/calendar.calendarlist.readonly)예요. 목록은 무엇을 가져오고 어디로 보낼지 고르는 창에 써요. 다른 구글 권한은 요청하지 않아요. 예전에 일정 권한만으로 연결했다면 캘린더 목록은 한 번 다시 연결해야 보여요.
  • 하는 일: 페어리에서 넣은 일정을 여러분이 고른 캘린더 하나에 넣어요. 처음에는 기본 캘린더예요. "보내지 않기"도 고를 수 있어요. 페어리에서 고치거나 지우면 구글에서도 고치고 지워요. 보낼 캘린더를 바꾸면 이미 보낸 일정을 새 캘린더로 옮겨요. 고치고 지우는 것은 페어리가 직접 넣은 일정(구글 일정 id를 적어 둔 것)뿐이에요. "구글 캘린더 일정 가져오기"를 켜 두면 가져오기로 고른 캘린더들의 일정을 읽어 와요. 처음에는 기본 캘린더만 골라져 있어요. 지난 7일부터 앞으로 60일까지 일정을 15분마다 읽어 와요. 그 캘린더 이름과 색을 달아 페어리 일정 목록과 달력에 보이고 알려 줘요. "구글 캘린더 일정 가져오기"는 연결할 때 켜지고 따로 끌 수 있어요. 같은 일정이 두 캘린더에 있으면 하나만 보여요. 읽어 온 일정은 페어리에서 고치거나 지우지 않아요. 구글로 쓰지 않아요.
  • 보내는 것: 일정 제목, 시작과 끝 시각, 이 컴퓨터의 시간대, 팝업 알림 시각이에요. 메모와 할 일은 보내지 않고, .ics로 가져온 일정도 구글로 보내지 않아요.
  • 읽는 것: 캘린더 목록의 이름과 색, 그리고 가져오기를 켠 캘린더의 일정 제목과 시각만 읽어요. 설명, 장소, 참석자는 읽지 않아요.
    자세히 보기캘린더 목록에서 캘린더마다 id, 이름(내가 바꾼 이름), 색, 내 권한(내 것, 쓰기 가능, 읽기만), 기본 캘린더인지, 숨겼는지만 읽어요. 가져오기를 켰을 때는 가져오기로 고른 캘린더들의 일정에서 제목, 시작과 끝 시각(종일 여부), 일정 식별자(id, iCalUID), 상태만 읽어요. 설명, 장소, 참석자, 첨부, 고르지 않은 캘린더의 일정, 캘린더 설정과 공유는 읽지 않아요. 읽은 것은 이 컴퓨터의 저장 파일에 두어요. 서버 백업을 직접 올리면 그 파일 안에 함께 들어가요. 가져오기를 끄거나 그 캘린더를 빼거나 연결을 끊으면 이 컴퓨터에서 지워요. 서버 백업 안의 것은 그 백업을 지울 때 지워져요. 서버 백업을 올리는 경우 말고 기본으로는 AI 대화, "오늘 뭐부터", 계획 다듬기, 페어리 도구를 포함해 어디로도 보내지 않아요. 설정의 "AI가 구글 일정도 볼 수 있게"(처음에는 꺼져 있어요)를 여러분이 켠 경우에만 보내요. 그때는 그 기능을 쓸 때 읽어 온 일정의 제목과 시각을 여러분이 고른 AI로 보내요. 클라우드 AI면 그 회사로 가요. 무료 AI(이 컴퓨터에서 도는 모델)면 이 컴퓨터 밖으로 나가지 않아요. 끄면 바로 다시 보내지 않아요. 페어리가 넣은 일정에는 구글이 돌려주는 식별자만 적어 둬요.
  • 연결 방식: 기본 브라우저에서 허락을 받아요. 구글 비밀번호는 페어리가 보지 않아요.
    자세히 보기구글의 설치 앱용 OAuth(PKCE, 이 컴퓨터의 127.0.0.1 루프백 주소)를 써요. 구글 비밀번호는 페어리가 보지 않아요.
  • 보관: 오래 쓰는 열쇠 토큰만 데이터 폴더에 둬요. 잠깐 쓰는 토큰은 메모리에만 있어요. 토큰은 백업, 설정, 진단 기록에 넣지 않아요.
    자세히 보기오래 쓰는 토큰(refresh token)만 데이터 폴더의 google-token.json에 둬요. 권한은 0600이고, 운영체제 열쇠로 암호화할 수 있으면 암호화해요. 잠깐 쓰는 토큰(access token)은 메모리에만 있어요. 토큰은 백업, 설정, 진단 기록에 넣지 않아요. 캘린더 토큰은 페어리 서버로 보내지 않아요. 그래서 이 컴퓨터와 구글 사이에서만 오가요.
  • 연결 끊기: 설정의 "연결 끊기"를 누르면 이 컴퓨터의 토큰을 지워요. 구글에서도 권한을 거둬요. 이미 보낸 일정은 구글 캘린더에 그대로 남아요. 필요하면 구글 캘린더에서 지워 주세요.
    자세히 보기구글에서 권한을 거둘 때 oauth2.googleapis.com/revoke를 써요. 구글 계정 → 보안 → 서드 파티 연결에서 거둬도 돼요.

Limited Use

페어리가 구글 API에서 받은 정보를 쓰고 다른 앱으로 옮기는 일은 Limited Use 요구 사항을 포함한 Google API 서비스 사용자 데이터 정책을 따라요.

fairy’s use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

  • 구글 사용자 데이터는 다음 일에만 써요. 일정을 넣고 고치고 지우는 일이 있어요. 가져오고 보낼 캘린더를 고르도록 캘린더 목록을 보여 주는 일이 있어요. 구글 일정을 페어리에서 보여 주고 알려 주는 일도 있어요. 여러분이 켠 경우에만 고른 AI가 여러분의 일정을 보고 돕는 일이 있어요. 여러분이 직접 올린 서버 백업을 되살리는 일도 있어요.
  • 팔지 않아요. 여러분이 "AI가 구글 일정도 볼 수 있게"를 켜고 고른 AI로 보내는 것, 그리고 직접 누르고 따로 동의해 올린 서버 백업 말고는 다른 사람에게 넘기지 않아요. 서버 백업을 올리지 않으면 읽어 온 구글 일정은 이 컴퓨터를 떠나지 않아요. 올린 서버 백업 파일에는 구글에서 읽어 온 일정이 들어 있을 수 있어요. 그 파일은 암호화되어 있고 암호 키는 운영자가 서버 설정에 두고 관리해요. 그 백업을 올린 사람이 되살릴 때만 쓰고, 운영자는 열어 보거나 다른 데 쓰지 않아요. 올린 백업은 설정 → 데이터와 계정에서 "지우기"로 언제든 지울 수 있어요.
  • 광고(맞춤 광고, 리타기팅 포함)나 신용 평가, 대출 판단에 쓰지 않아요.
  • AI나 머신러닝 모델을 만들거나 개선하거나 학습시키는 데 쓰지 않아요.

나누는 곳

개인정보를 팔거나 빌려주지 않아요. 서버 기능을 켜지 않으면 만든 사람에게 오는 데이터는 없어요. 켠 경우에도 보내는 곳은 두 군데뿐이에요. 하나는 "서버 기능을 켰을 때"와 "맡기는 곳과 나라 밖으로 가는 것"에 적은 곳이에요. 다른 하나는 "컴퓨터 밖으로 나가는 것"에 적은, 여러분이 그 기능을 쓸 때 고른 곳이에요. 그 밖으로는 보내지 않아요. 친구 기능이 열리면 친구에게는 내 닉네임, 기기 코드, 내가 켠 바쁜 시간이 보여요. 제목까지 켠 친구에게는 일정 제목도 보여요.

보관 기간과 지우기

이 컴퓨터의 데이터는 여러분이 지울 때까지 남아요. 서버 기능을 켰다면 서버에 있는 것은 아래 기간만 둬요.

  • 할 일, 메모, 일정은 앱에서 지울 수 있어요.
  • 설정 → 데이터와 계정 → "AI 기록 지우기"는 Claude Code와 Codex가 페어리 전용 폴더에 남긴 대화 기록을 지워요. 그 AI 회사 쪽에 남은 기록은 그 회사가 정한 방법으로 지워요.
  • 구글 캘린더는 위의 "연결 끊기"로 토큰을 지우고 권한을 거둬요.
  • 진단 기록은 1MB가 넘으면 오래된 파일을 지우며 돌려서, 합쳐 2MB를 넘지 않아요.
  • 앱을 지워도 데이터 폴더는 남아요(다시 설치하면 이어서 써요). 모두 지우려면 앱을 지운 뒤 위의 데이터 폴더를 지워요.
  • 서버 계정 지우기(탈퇴)는 설정 → 데이터와 계정의 "서버 계정 지우기"로 바로 할 수 있어요. 서버의 계정, 로그인 연결, 코인과 물건 기록, 쪽지함, 채팅 이용권, 서버 백업(파일 포함), 신고한 대화를 지금 바로 지워요. 친구 기능이 열리면 친구, 신청, 차단, 바쁜 시간과 일정 제목, 펫 놀러 가기 카드도 함께 지우고, 상대에게 보낸 선물 기록은 내 번호만 지워 상대 쪽에 남겨요. 이 컴퓨터의 데이터는 남아요. 지운 계정을 다시 살리는 기능은 없어요.
  • 서버 백업은 계정마다 최근 2개만 두고, 1년 동안 서버를 쓰지 않은 계정의 서버 백업은 지워요(지우기 30일 전에 앱의 서버 백업 목록에 알려요). "지우기"를 누르면 바로 지워요.
  • 신고한 대화는 운영자가 받은 날부터 30일 뒤에 지워요. 서버 계정을 지우면 바로 지워요.
  • 운영 기록은 1년 동안 둬요. 서버 계정을 지워도 그 기간까지 남을 수 있어요.
  • 나이 답을 만 14세 미만으로 바꾸면 서버 기능이 꺼지고, 서버 계정을 지우도록 안내해요.
  • 로그인하지 않은 기기 계정은 앱을 지우거나 기기를 바꾸면 되찾을 수 없어요. 그래서 1년 동안 한 번도 쓰지 않은 로그인 없는 기기 계정은 서버가 정기적으로 확인해 지워요. 구글로 로그인해 둔 계정은 이 자동 지우기 대상이 아니고, 직접 지울 때까지 남아요.
  • 서버의 기록은 데이터베이스에서 지우고, 서버 백업 파일은 디스크에서 파일을 지워요. 이 컴퓨터의 데이터는 직접 지워요.
  • 장애에 대비한 서버 데이터베이스 사본은 7일 뒤 지워요. 그래서 서버 계정을 지워도 그 사본에는 최대 7일 남을 수 있어요.
    자세히 보기서버 백업 파일은 이 사본에 들어 있지 않아요. 그 파일의 외장 디스크 사본은 서버에서 파일을 지운 뒤 하루 안에 같이 지워져요.
  • 쪽지함에서 연 쪽지는 1년 뒤 지워요.
  • 로그인 세션(토큰의 해시)은 로그아웃하면 지워요. 오래 쓰지 않아 못 쓰게 된 세션도 서버 계정을 지울 때까지 남아요.

내 정보에 대한 권리

서버에 있는 내 정보를 보여 달라고 하거나, 고치거나, 지우거나, 처리를 멈춰 달라고 할 수 있어요. 아래 문의(GitHub 이슈나 이메일)로 알려 주세요. 앱 안에서 바로 할 수 있는 것은 이것들이에요.

  • 서버 백업 지우기: 설정 → 데이터와 계정의 서버 백업 목록에서 "지우기"
  • 서버 계정 지우기: 설정 → 데이터와 계정의 "서버 계정 지우기"
  • 로그아웃: 설정 → 데이터와 계정의 "로그아웃" (이 기기의 로그인을 서버에서 지워요)
  • 나이 구분 바꾸기: 설정 → 데이터와 계정의 "나이 바꾸기"
  • 따로 한 동의 거두기: 서버 백업은 올리지 않으면 되고, 이미 올린 것은 "지우기"로 지워요. 채팅 이용권은 쓰지 않으면 되고, 신고는 누르지 않으면 돼요. 이미 보낸 신고는 문의로 지워 달라고 하거나 30일 뒤 저절로 지워지길 기다려 주세요.

안전하게 지키는 법

  • 서버에는 기기 토큰과 세션 토큰의 해시만 둬요. 앱 쪽 토큰은 운영체제 열쇠로 암호화해 둬요.
  • 서버 백업은 서버 디스크에 암호화해 저장해요. 암호 키는 서버 설정 파일에 있고 운영자가 관리해요.
    자세히 보기서버 백업은 서버 디스크에 AES-256-GCM으로 암호화해 저장해요. 암호 키는 서버 설정 파일에 있고 운영자가 관리해요.
  • API 키와 로그인 비밀 같은 비밀값은 서버 설정 파일에만 두고, 공개 저장소에는 넣지 않아요.
  • 요청이 너무 많으면 기기와 계정 단위로 막아요.
  • 운영자 작업은 모두 기록으로 남겨요.
  • 앱과 서버 사이의 연결은 암호화(HTTPS)돼요.

자세히 보기브라우저에는 고른 언어(localStorage)와 15분 동안의 최신 버전 정보(sessionStorage)만 저장해요. 최신 버전을 알려고 브라우저가 GitHub API에 물어봐요.

어린이와 나이

앱은 나이와 상관없이 쓸 수 있어요. 서버 기능(친구와 선물 포함)은 만 14세 이상만 쓰고, 만 14세 미만은 서버 계정 없이 써서 서버로 아무것도 보내지 않아요. 나이는 직접 고른 답을 기준으로 하고, 확인하는 절차는 없어요. 보호자 동의를 받는 절차도 아직 없어요. 채팅 이용권은 만 18세 이상만 쓰고, 만 18세 미만은 지금처럼 내 컴퓨터의 AI 프로그램으로 대화해요.

바뀔 때

이 방침을 바꾸면 이 페이지와 위의 시행일을 고쳐요. 바뀐 내용은 공개 저장소 milcho0604/fairy의 기록에도 남아요.

방침을 바꾸면 약관을 바꿀 때와 같은 방법과 기간으로 앱의 공지 창과 홈페이지에 알려요.
